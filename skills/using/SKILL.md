# interx-deck: 공통 규칙과 갈래

엔진과 자산은 플러그인 폴더 `${CLAUDE_PLUGIN_ROOT}/` 에 하나뿐이다. 아래에서 `scripts/`, `assets/` 는 이 폴더 기준.

## 개인 설정 (플러그인 밖, 사람마다)
- 위치 `~/.claude/interx-deck/profile/`. 플러그인을 새 판으로 바꿔도 남는다
  - `profile.json`: 작성자 {team, name, title}
  - `okr/repos.json`: OKR 근거를 모을 폴더 목록 (선택)
  - `projects/<과제>/README.md`: 그 과제만의 규칙(경로, 문서 번호, 양식 원본 위치, 마스킹 규칙). 그 과제 덱을 만들 때 공통 규칙 다음에 읽는다
- 처음 쓰는 사람: profile.json 이 없으면 소속, 이름, 직급을 묻고 `save_profile_author(소속, 이름, 직급)` 로 저장.

## 0. 갈래 고르기
| 만드는 것 | 갈래 |
|---|---|
| 보고 자료, 결과 보고, 과제 개요, 수행계획, 착수 보고, 고객 보고, 주간보고, 성능 비교, 화면 설명 | `interx-deck:report` |
| 설계 문서, 시스템 구성도, 아키텍처도, 데이터 흐름도, AAS 구조도, 다른 양식 문서(PM03 등)의 본문 장 | `interx-deck:design` |
| 월간 Individual OKR 덱 (IX_OKR_Individual_OKR) | `interx-deck:okr` (전월 덱을 틀로 쓰는 다른 엔진. 아래 2 ~ 6절 대신 그 스킬의 규칙) |
- 한 덱에 보고형 장과 구성도 장이 섞이면 report 와 design 을 같이 읽는다 (엔진, 관문이 같음)

## 1. 목적과 범위
- INTERX 기본 양식(템플릿 14장의 부품)과 회사 참고 덱(삼성SDI Text-to-SQL 과제계획, 생성형 AI 및 AI Agent 활용 방안, 상신브레이크 KOM)의 틀, 부품, 수치를 그대로 쓴다
- 모든 상자, 선, 글자는 PowerPoint 에서 바로 고칠 수 있는 도형. 연결선은 양 끝이 도형에 붙음. 그림 파일은 아이콘, 로고, 화면 캡처뿐
- AAS 에 매이지 않는다. AAS 칩, `bundle` 기본 이름, `aas_shell`, AAS 배지와 로고 아이콘(aas_*, badge_*, label_ish, logo_eclass, logo_iec61360, rdf)만 AAS 과제용

## 2. 만드는 순서 (report, design 공통)
0. **작성자 정보를 먼저 확인한다.** 덱마다. 첫 선택지는 개인 설정 값 `profile_author()`(없으면 묻고 저장). `Deck(author="소속 / 이름 직급")` (없으면 멈춤). 같은 질문지에서 파일명과 버전도 묻는다 (첫 판 0.1.0)
1. **`scripts/example_build.py` 를 과제 폴더에 `build.py` 로 복사해 시작한다.** 모든 장 유형과 부품이 들어 있고 관문을 통과한다
2. 절과 장: `d.section("절 이름")` 다음 `d.page("장 주제", lead="요약 한 줄", doc=구성도면 True)`. 한 장에 메시지 하나
3. 자리는 자동 배치 함수로만 (`report_panels`, `DocGrid`). 좌표를 손으로 쓰지 않는다. 단위 인치
4. **`python -I scripts/gate.py <build.py> <장 수>`** 가 "결과: 통과" 할 때까지 고친다. 기준을 낮추지 않는다(`strict=False`, `--soft` 는 자체 시험 전용)
5. 렌더 그림을 9절 장 검토 목록으로 본다
6. 넘기기 전 독립 검토 2건: 사실 정확성(원천 대조), 처음 읽는 사람(이 과제를 모르는 사람이 "이게 무슨 말이야" 할 문장 목록)

**만든 pptx 를 PowerPoint COM 으로 직접 열지 않는다.** 회사 DRM 이 암호화한다(SCDSA004). render.ps1 은 버리는 사본만 연다. 최종본은 PDF 로 보낸다. 관문이 pptx 옆에 같은 이름의 PDF 를 만든다 (`render.ps1 -Pdf`). 외부 서비스에 보낸 내용은 보관될 수 있으니 회사 데이터, 고객명, 설비명은 공개 범위가 정해지기 전에 내보내지 않는다.

## 3. 덱 구성 (자동)
| 순서 | 장 | 레이아웃 | 만드는 곳 |
|---|---|---|---|
| 1 | 표지 | 3_사용자 지정 레이아웃 | `d.cover(제목, "2026.11.10")` 날짜는 덱 기준일(오늘 자동 아님), 제목 한 줄(약 18자) |
| 2 | 목차 | 5_contents-02 | 저장이 채움: 절마다 주황 번호, 절 이름, 그 아래 장 주제(끝 괄호 뺌). 페이지 범위는 적지 않음. 절 6개부터 두 열 |
| 3 ~ | 본문 | 본문_소제목 O | `d.page(...)` (보고형, 구성도 같은 틀) |
| 끝 | Thank you | 앤드페이지_다크네이비 | 저장이 붙임 |
- 다른 양식 문서에 본문 장만 옮겨 넣는 빌더는 `Deck(author, parts_only=True)` (design 갈래 참고)
- 이 넷 밖의 레이아웃은 `Deck` 이 막고 check.py 가 장 순서까지 잡는다. 저장한 뒤 `d.page` 를 더하면 멈춤

## 4. 제목
| 자리 | 규칙 | 예 |
|---|---|---|
| 대제목 | 절 이름. 같은 절은 같은 글. "번호. 명사구", 번호만 주황 | 2. 시스템 구성 |
| 소제목 | "번호-번호. 명사구 (기준 또는 대상)". 문장, "~에서", "~때" 끝 금지 | 2-1. 구성 및 수집 흐름 |
| 요약 줄 | 장 메시지 한 문장, 명사형 끝맺음, 괄호로 끝내지 않음, 한 줄 | ~수집 시스템을 개발함 |
| 패널 제목 | 명사구. 그 안 목록 제목이 패널 제목을 되풀이하지 않음 | 수집 계획 (INTERX.DA 수신) |
| 날짜 | 소제목 끝 괄호 | 4-2. 진행 현황 (2026-11-04 기준) |
- 번호는 손으로 쓰지 않는다. 요약은 띠 아래 줄(`lead`), 띠 아래에 다른 소제목을 더하지 않는다. 머리말("핵심:", "오늘 정할 것:") 금지

## 5. 글쓰기와 내용
**글쓰기**
- 한국어, 개조식, 명사형 끝맺음. 가운뎃점, 긴 줄표 금지(쉼표나 괄호로). '~축으로' 금지, 명사 나열 '~과 ~' 는 '및'
- 모든 숫자에 단위. 표 숫자에는 대상과 조건을 같이
- 처음 나오는 용어는 그 자리에서 풀어 씀. 원천 필드명과 공식 명칭을 그대로, 새 용어를 만들지 않음
- 표 칸은 짧게, 긴 설명은 표 밖. 새 지표는 그 장 아래 정의 한 줄, 계산식은 `Col.formula`
- 전문가 대상 어휘: 비슷한 → 유사한, 맞힘 → 적중, 놓침 → 미검출, 헛경보 → 오경보, 쓰임 → 용도, 읽는 법 → 해석. 제목에 '쉽게' 같은 말 금지('용어 설명')

**내용**
- 두괄식: 결론 먼저, 근거는 뒤. 합쳐도 되는 장은 합침, 채우기용 장 금지
- 확인된 사실만. 추측, 기대 효과, 미확인 원인은 쓰지 않음(확인 못 한 것은 '확인 필요' 로 표기하거나 보고에서만 알림)
- 불안정하거나 실패한 결과는 본문에서 뺌(필요하면 부록). 고객 제출 자료에 내부 실수와 시행착오 노출 금지
- 의사결정자가 정할 일(일정, 우선순위)은 제안하지 않고 근거만
- 현재 상태 하나만. 옛 판 내용이 섞이지 않게
- **중요한 말, 필요한 내용, 알아야 할 내용만**. 쓴 사람만 아는 내부 이름, 파일 확장자 나열, 괄호 부연은 빼거나 풀어 쓴다. 한 문단에 괄호 부연 셋 이상이면 check.py 실패

**파일**
- **파일 이름 `YYYYMMDD_파일명_작성자_v버전`**. `OUT = d.filename("파일명", "0.9.0", 폴더)` 로 만든다. 규칙과 다르면 관문(check)이 실패
  - 날짜는 만든 날, 파일명은 띄어쓰기와 `_` 없이, 작성자는 이름만
  - 버전: 첫 판 0.1.0, 고친 판은 끝자리, 내용이 늘면 가운데 자리, 확정본 1.0.0. 올릴 자리는 사용자에게 확인
- 저장 위치는 사용자가 정한 폴더, 없으면 지금 작업 폴더. pptx 와 PDF 가 나란히 생긴다. 렌더 그림은 `%TEMP%` 에만 (쌓지 않음)
- 새 판을 만들면 옛 판은 보관 폴더로. 백업본을 따로 만들지 않음
- 바뀐 사실이 있으면 모든 자료에서 옛 값을 찾아 같이 고침

**글자 (저장이 자동)**
- 글꼴 Noto Sans KR 하나(굵기 이름 글꼴은 굵게 켬으로), 글상자 세로 중간 맞춤, 줄 간격 1.25 또는 1.5(`text(..., line=1.5)`)
- 한글 줄 바꿈: 글 조각마다 `lang="ko-KR"`, 문단마다 `latinLnBrk="0"`(빠지면 낱말 중간에서 줄이 바뀜)
- 마침표로 끝난 문장 다음 문장은 새 줄, 한 줄을 넘는 문장은 쉼표 바로 뒤에서 끊음(`ko_breaks`)
- 글자 크기는 기본 크기만: 20 목차 번호와 핵심 수치, 14 목차 절 이름, 12 요약 줄과 패널 머리, 10.5 핵심 문장 띠와 작은 제목과 식, 9 카드 제목과 이름표, 8.16 서버 상자, 8 번호 원과 이름표 줄, 7.26 표와 본문 작은 글, 6.35 아이콘 이름과 각주와 조건 문구, 5.44 EAC

## 7. 사람이 PowerPoint 에서 만든 느낌
| 하지 말 것 | 대신 |
|---|---|
| 패널마다 표만 | 아이콘 규칙 목록, 번호 카드, 이름표 묶음. 표는 칸이 필요한 것만 |
| 장마다 남색 배지나 큰 숫자 | 숫자가 메시지인 장에만 `kpis`, 덱 본문의 1/5 장까지 |
| 같은 종류 상자 높이가 제각각 | 같은 장 같은 종류는 같은 높이(자동). 모든 패널에 블록을 넣은 뒤 `done()` |
| 캡처 위 번호 원만, 번호 자리가 제각각 | 영역 네모와 왼쪽 위 모서리 번호(자동) |
| 도식 오른쪽에 떨어진 설명 열 | 설명은 가리키는 자리 옆 |
| 내용이 꼬리말 선에 붙음 | 꼬리말 선 위 0.30 in 비움(자동) |

## 8. 자산
- 아이콘 `assets/icons` 158개, 로고 `assets/logos` 10개. 모양과 이름은 각 폴더 `_catalog.png`. 한 장 안에서 같은 아이콘을 두 뜻으로 쓰지 않음(저장이 잡음)
- 로고: interx_tagline, 기술(minio, kserve, kubeflow, logo_postgresql, influxdb, react_flow), 협력 기관(dgtp, kitech, sangsin_brake). 고객사 로고는 넣지 않음(그 고객 자료에서 사용자가 줄 때만)
- 템플릿 원본 도형은 `d.clone(s, 장번호, text=..., shape_id=)`

## 9. 관문 (gate.py) 과 장 검토 목록
| 단계 | 잡는 것 |
|---|---|
| 저장 (`Deck.save`, 엄격) | 겹침, 선이 상자를 지남, 놓을 자리 없는 번호와 설명, 선 없는 구성도 상자, 패널 빈 곳 0.5 in 넘음, 칸보다 긴 글, 두 뜻 아이콘, 목록 제목 되풀이, 핵심 수치 남발, 캡처 번호 겹침, 같은 종류 상자 높이 다름 |
| check.py | 장 순서, 16:9, 제목 규칙, 글꼴 하나, 중간 맞춤, 줄 간격, 한글 줄 바꿈 설정, 기본 크기 밖 글자, 넘치는 글자, 글보다 높은 표 행, 바닥 선 여백, 괄호 부연, 번호 원 지름, 붙지 않은 연결선, SVG 만 있는 그림, 장 밖 도형, 치우침. 주의만: 마지막 줄에 낱말 하나, 표 장 35% 넘음, 같은 구도 3장 연속 (렌더로 보고 판단) |
| check_ban.py | 금지 표현 (차트 글 포함) |
| render.ps1 | 장마다 PNG, 모아 보기 sheet.png (`%TEMP%/interx_gate/<덱>/`), pptx 옆 PDF |
- build.py 마지막 줄은 `print(OUT)`
- **장 검토 목록** (자동 검사가 못 보는 것): 장마다 메시지 하나와 그 요약 줄, 선 흐름과 번호 순서, 같은 것은 같은 이름과 색과 아이콘, 빈 칸을 행 높이나 큰 글자로 메우지 않음, 캡처 네모가 맞는 자리, 목차가 핵심만 담음, 처음 보는 사람이 이해함

## 10. 템플릿 다시 만들기
- 템플릿 원본이 바뀌면 `python -I scripts/make_template.py <원본.pptx> assets/interx_template.pptx`. SVG 만 있는 예전 덱은 `--png-fallback <덱> <출력>`

## 11. 자주 하는 실수
| 실수 | 바로잡기 |
|---|---|
| 빈 파일에서 시작 | `example_build.py` 복사 |
| 작성자를 확인하지 않음, 템플릿 예시 값(AX Data Design)을 씀 | 2절 0번, 개인 설정 |
