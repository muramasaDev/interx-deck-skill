# interx-deck: 공통 규칙과 갈래

엔진과 자산은 플러그인 폴더 `${CLAUDE_PLUGIN_ROOT}/` 에 하나뿐이다. 아래에서 `scripts/`, `assets/` 는 이 폴더 기준.

## 개인 설정 (플러그인 밖, 사람마다)
- 위치 `~/.claude/interx-deck/profile/`. 플러그인을 새 판으로 바꿔도 남는다
  - `profile.json`: 작성자 {team, name, title}
  - `okr/repos.json`: OKR 근거를 모을 폴더 목록 (선택)
  - `projects/<과제>/README.md`: 그 과제만의 규칙(경로, 문서 번호, 양식 원본 위치, 마스킹 규칙). 그 과제 덱을 만들 때 공통 규칙 다음에 읽는다
- 처음 쓰는 사람: profile.json 이 없으면 소속, 이름, 직급을 묻고 `save_profile_author(소속, 이름, 직급)` 로 저장.

## 0. 갈래 고르기
| 만드는 것 | 갈래 |
|---|---|
| 보고 자료, 결과 보고, 과제 개요, 수행계획, 착수 보고, 고객 보고, 주간보고, 성능 비교, 화면 설명 | `interx-deck:report` |
| 설계 문서, 시스템 구성도, 아키텍처도, 데이터 흐름도, AAS 구조도, 다른 양식 문서(PM03 등)의 본문 장 | `interx-deck:design` |
| 월간 Individual OKR 덱 (IX_OKR_Individual_OKR) | `interx-deck:okr` (전월 덱을 틀로 쓰는 다른 엔진. 아래 2 ~ 6절 대신 그 스킬의 규칙) |
- 한 덱에 보고형 장과 구성도 장이 섞이면 report 와 design 을 같이 읽는다 (엔진, 관문이 같음)

## 1. 목적과 범위
- INTERX 기본 양식(템플릿 14장의 부품)과 회사 참고 덱(삼성SDI Text-to-SQL 과제계획, 생성형 AI 및 AI Agent 활용 방안, 상신브레이크 KOM)의 틀, 부품, 수치를 그대로 쓴다
- 모든 상자, 선, 글자는 PowerPoint 에서 바로 고칠 수 있는 도형. 연결선은 양 끝이 도형에 붙음. 그림 파일은 아이콘, 로고, 화면 캡처뿐
- AAS 에 매이지 않는다. AAS 칩, `bundle` 기본 이름, `aas_shell`, AAS 배지와 로고 아이콘(aas_*, badge_*, label_ish, logo_eclass, logo_iec61360, rdf)만 AAS 과제용

## 2. 만드는 순서 (report, design 공통)
0. **작성자 정보를 먼저 확인한다.** 덱마다. 첫 선택지는 개인 설정 값 `profile_author()`(없으면 묻고 저장). `Deck(author="소속 / 이름 직급")` (없으면 멈춤). 같은 질문지에서 파일명과 버전도 묻는다 (첫 판 0.1.0)
1. **`scripts/example_build.py` 를 과제 폴더에 `build.py` 로 복사해 시작한다.** 모든 장 유형과 부품이 들어 있고 관문을 통과한다
2. 절과 장: `d.section("절 이름")` 다음 `d.page("장 주제", lead="요약 한 줄", doc=구성도면 True)`. 한 장에 메시지 하나
3. 자리는 자동 배치 함수로만 (`report_panels`, `DocGrid`). 좌표를 손으로 쓰지 않는다. 단위 인치
4. **`python -P scripts/gate.py <build.py> <장 수>`** (Mac 은 `python3`) 가 "결과: 통과" 할 때까지 고친다. 기준을 낮추지 않는다(`strict=False`, `--soft` 는 자체 시험 전용)
5. 렌더 그림을 9절 장 검토 목록으로 본다
6. **사람이 쓴 덱 검토**: 관문이 만든 `text.md` 와 `sheet.png` 로 `references/review_prompt.md` 지시문을 검토 에이전트에 준다. 고칠 곳을 모두 고치고 관문을 다시 돌린 뒤 새 에이전트로 같은 검토를 되풀이한다
   - '그대로 사용 가능' 이면 넘긴다. 3번 되풀이해도 남으면 남은 표를 사용자에게 보여 주고 넘긴다 (검토자는 회마다 더 작은 것을 찾으므로 끝없이 돌리지 않음)
   - 고칠 때 아래 '검토에서 자주 나온 결함' 을 덱 전체에 한 번에 적용한다
7. 넘기기 전 사실 정확성 검토 1건 (원천 대조). 6과 같은 에이전트에 근거 자료 경로를 주면 한 번에 끝낼 수 있음

**만든 pptx 를 PowerPoint COM 으로 직접 열지 않는다.** 회사 DRM 이 암호화한다(SCDSA004). render.py 는 버리는 사본만 연다. 최종본은 PDF 로 보낸다. 관문이 pptx 옆에 같은 이름의 PDF 를 만든다 (`render.py --pdf`). 외부 서비스에 보낸 내용은 보관될 수 있으니 회사 데이터, 고객명, 설비명은 공개 범위가 정해지기 전에 내보내지 않는다.

## 3. 덱 구성 (자동)
| 순서 | 장 | 레이아웃 | 만드는 곳 |
|---|---|---|---|
| 1 | 표지 | 3_사용자 지정 레이아웃 | `d.cover(제목, "2026.11.10")` 날짜는 덱 기준일(오늘 자동 아님), 제목 한 줄(한글 약 15자, 넘으면 멈춤) |
| 2 | 목차 | 5_contents-02 | 저장이 채움: 절마다 주황 번호, 절 이름, 그 아래 장 주제(끝 괄호 뺌). 페이지 범위는 적지 않음. 절 6개부터 두 열 |
| 3 ~ | 본문 | 본문_소제목 O | `d.page(...)` (보고형, 구성도 같은 틀) |

- 다른 양식 문서에 본문 장만 옮겨 넣는 빌더는 `Deck(author, parts_only=True)` (design 갈래 참고)
- 이 넷 밖의 레이아웃은 `Deck` 이 막고 check.py 가 장 순서까지 잡는다. 저장한 뒤 `d.page` 를 더하면 멈춤

## 4. 제목
| 자리 | 규칙 | 예 |
|---|---|---|
| 대제목 | 절 이름. 같은 절은 같은 글. "번호. 명사구", 번호와 글 모두 회색 | 2. 시스템 구성 |
| 소제목 | "번호-번호. 명사구 (기준 또는 대상)". 문장, "~에서", "~때" 끝 금지 | 2-1. 구성 및 수집 흐름 |
| 요약 줄 | 장 메시지 한 문장, 명사형 끝맺음, 괄호로 끝내지 않음, 한 줄 | ~수집 시스템을 개발함 |
| 패널 제목 | 명사구. 그 안 목록 제목이 패널 제목을 되풀이하지 않음 | 수집 계획 (INTERX.DA 수신) |
| 날짜 | 소제목 끝 괄호 | 4-2. 진행 현황 (2026-11-04 기준) |
- 번호는 손으로 쓰지 않는다. 요약은 띠 아래 줄(`lead`), 띠 아래에 다른 소제목을 더하지 않는다. 머리말("핵심:", "오늘 정할 것:") 금지

## 5. 글쓰기와 내용
**글쓰기**
- 한국어, 개조식, 명사형 끝맺음. 가운뎃점, 긴 줄표 금지(쉼표나 괄호로). '~축으로' 금지, 명사 나열 '~과 ~' 는 '및'
- 모든 숫자에 단위. 표 숫자에는 대상과 조건을 같이
- 처음 나오는 용어는 그 자리에서 풀어 씀. 원천 필드명과 공식 명칭을 그대로, 새 용어를 만들지 않음
- 표 칸은 짧게, 긴 설명은 표 밖. 새 지표는 그 장 아래 정의 한 줄, 계산식은 `Col.formula`
- 전문가 대상 어휘: 비슷한 → 유사한, 맞힘 → 적중, 놓침 → 미검출, 헛경보 → 오경보, 쓰임 → 용도, 읽는 법 → 해석. 제목에 '쉽게' 같은 말 금지('용어 설명')
- 말투는 보고서 어휘로. 구어 부사(늘, 딱, 쭉, 좀, 그냥, 그만큼)와 '새 ~', '옛 ~' 은 빼거나 역할 이름으로 (금지 표현 검사가 잡음)
  - 예: '설비는 늘 비슷한 온도' → '설비별 온도 유사', '새 기준값' → '보정 기준값'
  - 고쳐 → 보정, 만듦 → 생성 또는 작성, 잡음 → 반영, 따라감 → 추종, ~쪽 → ~측
- 읽기 쉬운 문장 네 가지. 개조식 명사형 끝맺음은 그대로 지킴
  - 연결어 살리기: 앞뒤 관계(원인, 대조, 조건)를 '~하여', '~이나', '~이면' 으로 드러냄. '부하 증가, 응답 지연' → '부하 증가로 응답 지연'
  - 사물 의인화 금지: 사물이 말하거나 고르지 않음. '로그가 원인을 알려 줌' → '로그에서 원인 확인'
  - 명사 3개 이상 잇기 금지: 조사를 넣어 풀어 씀. '설비 상태 이력 조회 화면' → '설비 상태의 이력을 조회하는 화면'
  - 짝 단어 붙이기: 주어와 서술어, 꾸밈말과 꾸밈 받는 말 사이에 다른 말을 길게 넣지 않음. 길면 두 줄로 나눔
- 이름표, 패널 제목, 카드 제목은 명사(구)로 끝냄. '결론' 같은 같은 이름표를 장마다 되풀이하지 않음
- 계산식은 논문 표기: 한 글자 기호와 아래첨자(`J_{0}`), 곱하기 `\times`, 분수 `\frac{}{}`. 기호마다 `where` 에 뜻과 단위. 'x' 글자를 곱하기로 쓰지 않음

**사람이 쓴 덱 (사용자가 고치지 않아도 되는 수준)**
- 장 하나에 메시지 하나. 요약 줄이 결론, 본문은 그 근거만. 요약 줄을 본문이 되풀이하지 않음
- 숫자로 말함: '크게 줄어듦' 대신 '0.94 → 0.58 µm'. 수식어(다양한, 효과적으로, 획기적) 대신 사실
- 줄마다 다른 틀: 같은 낱말로 시작하는 줄 셋, 같은 길이로 맞춘 대구, '~을 통해' 되풀이는 사람이 쓰지 않음
- 이름표, 패널 제목은 그 장 내용을 담은 명사 ('결론' 되풀이 금지). 메모 줄은 꼭 필요한 조건과 출처만
- 쓴 사람만 아는 것 금지: 작업 과정, 파일 이름, 함수 이름, 시행착오, '확인해 보니'
- 독자가 쓰는 말로: 현업 원천 명칭 그대로, 처음 나오면 그 자리에서 풀어 씀. 영어 약어 남발 금지
- 화면 문구처럼 원문 그대로 옮긴 글은 `Deck(..., allow=[r"새 비밀번호", r"다시 시도하십시오\."])` 로 검사에서 뺀다 (범위를 좁게)
- 문장 검사(`check_text.py`)가 AI 투 수식어, 서술체(~습니다, ~한다.), 느낌표와 그림 문자를 실패로 잡고 '~을 통해', 의인화, 글 안 화살표, 명사 넷 잇기, 70자 넘는 줄, 같은 시작 셋을 주의로 알림

**검토에서 자주 나온 결함 (처음부터 피함)**
- 요약 줄의 범위와 본문 범위가 다름: 장 제목, 요약 줄, 패널이 같은 대상과 기간을 다룸 (4차 시험 요약 아래 1 ~ 4차 그림 금지)
- 시제: 끝난 일과 예정인 일을 섞지 않음. 기준일 뒤의 일은 '~하면', '예정' 으로. 표지 제목도 진행 보고면 '진행 보고'
- 같은 대상은 덱 전체에서 한 이름 (데이터 저장소, 서버 DB, 중앙 DB 를 섞지 않음). 같은 단위 하나 (건과 회를 섞지 않음)
- 처음 나온 용어와 조건은 그 장에서 풀어 씀 (회차, 끊김, 지연의 정의)
- 기준과 결과를 구분: '목표 95% 이상', '결과 95.7%' 를 따로. 기준은 판정하는 장에 함께
- 현행 문제와 개선은 한 줄씩 짝. 표를 아이콘이나 이름표로 되풀이하지 않음
- 같은 말을 한 장에 두 번 쓰지 않음 (요약 줄을 메모 줄이 되풀이 금지)
- 숫자끼리 맞춤: 합계, 비율, 날짜, 장 사이 같은 수
- 그림과 글이 맞음: 글에 쓴 경로(다시 전송 등)가 구성도에 있고, 구성도의 상자 이름이 글에 같은 이름으로

**내용**
- 두괄식: 결론 먼저, 근거는 뒤. 합쳐도 되는 장은 합침, 채우기용 장 금지
- 확인된 사실만. 추측, 기대 효과, 미확인 원인은 쓰지 않음(확인 못 한 것은 '확인 필요' 로 표기하거나 보고에서만 알림)
- 불안정하거나 실패한 결과는 본문에서 뺌(필요하면 부록). 고객 제출 자료에 내부 실수와 시행착오 노출 금지
- 의사결정자가 정할 일(일정, 우선순위)은 제안하지 않고 근거만
- 현재 상태 하나만. 옛 판 내용이 섞이지 않게
- **중요한 말, 필요한 내용, 알아야 할 내용만**. 쓴 사람만 아는 내부 이름, 파일 확장자 나열, 괄호 부연은 빼거나 풀어 쓴다. 한 문단에 괄호 부연 셋 이상이면 check.py 실패

**파일**
- **파일 이름 `제목_작성자_v버전_YYMMDD`**. `OUT = d.filename("제목", "0.9.0", 폴더)` 로 만든다 (띄어쓰기는 밑줄). 규칙과 다르면 관문(check)이 실패
  - 날짜는 만든 날 (연월일 여섯 자리), 제목의 띄어쓰기는 밑줄, 작성자는 이름만 (직급 빼고). "최종", "복사본" 금지
  - 버전: 첫 판 0.1.0, 고친 판은 끝자리, 내용이 늘면 가운데 자리, 확정본 1.0.0. 올릴 자리는 사용자에게 확인
- 저장 위치는 사용자가 정한 폴더, 없으면 지금 작업 폴더. pptx 와 PDF 가 나란히 생긴다. 렌더 그림은 임시 폴더에만 (쌓지 않음)
- 새 판을 만들면 옛 판은 보관 폴더로. 백업본을 따로 만들지 않음
- 바뀐 사실이 있으면 모든 자료에서 옛 값을 찾아 같이 고침

**글자 (저장이 자동)**
- 글꼴 Noto Sans KR 하나(굵기 이름 글꼴은 굵게 켬으로), 글상자 세로 중간 맞춤, 줄 간격 1.25 또는 1.5(`text(..., line=1.5)`)
- 한글 줄 바꿈: 글 조각마다 `lang="ko-KR"`, 문단마다 `latinLnBrk="0"`(빠지면 낱말 중간에서 줄이 바뀜)
- 마침표로 끝난 문장 다음 문장은 새 줄, 한 줄을 넘는 문장은 쉼표 바로 뒤에서 끊음(`ko_breaks`)
- 글자 크기는 기본 크기만: 20 목차 번호와 핵심 수치, 14 목차 절 이름, 12 요약 줄과 패널 머리, 10.5 핵심 문장 띠와 작은 제목과 식, 9 카드 제목과 이름표, 8.16 서버 상자, 8 번호 원과 이름표 줄, 7.26 표와 본문 작은 글, 6.35 아이콘 이름과 각주와 조건 문구, 5.44 EAC

## 7. 사람이 PowerPoint 에서 만든 느낌
| 하지 말 것 | 대신 |
|---|---|
| 패널마다 표만 | 아이콘 규칙 목록, 번호 카드, 이름표 묶음. 표는 칸이 필요한 것만 |
| 장마다 같은 '결론' 이름표 | 그 장 내용을 담은 명사 (저장이 3장 되풀이를 잡음) |
| 메모 줄을 '→' 로 시작 | '※' (엔진이 자동) |
| 흐름 없는 패널 사이 화살표 | 기본 없음. 결과가 다음 패널로 넘어갈 때만 `arrows=True` |
| 본문 절반 넘게 표 장 | 명세 표는 부록, 본문은 그림과 글 (check 실패) |
| matplotlib 기본 주황과 파랑 그래프 | 그리기 전 `mpl_style()` (기본 색 그림은 저장이 잡음) |
| 장마다 남색 배지나 큰 숫자 | 숫자가 메시지인 장에만 `kpis`, 덱 본문의 1/5 장까지 |
| 같은 종류 상자 높이가 제각각 | 같은 장 같은 종류는 같은 높이(자동). 모든 패널에 블록을 넣은 뒤 `done()` |
| 캡처 위 번호 원만, 번호 자리가 제각각 | 영역 네모와 왼쪽 위 모서리 번호(자동) |
| 도식 오른쪽에 떨어진 설명 열 | 설명은 가리키는 자리 옆 |
| 내용이 꼬리말 선에 붙음 | 꼬리말 선 위 0.30 in 비움(자동) |

## 10. 템플릿 다시 만들기
- 개인 설정 `profile.json` 에 `"template_source": "회사 양식 원본 경로"` 를 두면 원본이 더 새로울 때 덱을 만들 때마다 알림
- 템플릿 원본이 바뀌면 `python -P scripts/make_template.py <원본.pptx> assets/interx_template.pptx`. SVG 만 있는 예전 덱은 `--png-fallback <덱> <출력>`

## 10-2. 엔진 판 올린 뒤 다른 과제 덱 확인
- `python -P scripts/regress.py [build.py ...]` (없으면 개인 설정 `regress.txt` 의 목록): 새 엔진으로 다시 빌드해 check, 금지 표현, 문장 검사. 결과물은 임시 폴더 (`INTERX_OUT_DIR`), 원래 파일을 덮지 않음
- 실패한 과제 빌더는 그 과제 세션에서 고친다

## 10-3. Google Slides 로 보낼 때
- Google Drive 연결(커넥터)이 있으면 pptx 를 올려 Google 프레젠테이션으로 변환, 없으면 사용자가 Drive 에 올려 'Google 프레젠테이션으로 열기'
- Noto Sans KR 은 Slides 에 있음. 수식 상자는 Slides 에서 한 줄 식(대체 글)으로 보임: 수식이 메시지인 장은 PDF 를 함께 보냄
- 편집 가능한 차트는 Slides 에서 그림으로 바뀜 (숫자 고치기는 PowerPoint 에서)
