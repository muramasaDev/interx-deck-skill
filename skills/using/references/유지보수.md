# 유지보수 (덱을 만들 때는 읽지 않음)

- 템플릿 다시 만들기, 엔진 판 올린 뒤 다른 과제 덱 확인, 만든 덱의 글만 고치기, Google Slides 로 보내기

## 10. 템플릿 다시 만들기
- 개인 설정 `profile.json` 에 `"template_source": "회사 양식 원본 경로"` 를 두면 원본이 더 새로울 때 덱을 만들 때마다 알림
- 템플릿 원본이 바뀌면 `python -P scripts/make_template.py <원본.pptx> assets/interx_template.pptx`. SVG 만 있는 예전 덱은 `--png-fallback <덱> <출력>`

## 10-2. 엔진 판 올린 뒤 다른 과제 덱 확인
- `python -P scripts/regress.py [build.py ...]` (없으면 개인 설정 `regress.txt` 의 목록): 새 엔진으로 다시 빌드해 check, 금지 표현, 문장 검사, 렌더 그림을 기준과 비교. 결과물은 임시 폴더 (`INTERX_OUT_DIR`), 원래 파일을 덮지 않음. 이 모드에서는 엄격 실패도 저장해 그림을 비교하고 '엄격' 실패로 표시
- 그림 기준: 엔진을 고치기 전에 `regress.py --baseline` 한 번 (개인 설정 `regress_base/`). 바뀐 장은 기준과 나란히 붙인 `diff_sN.png` 를 남김. 의도한 변경이면 다시 `--baseline`
- 관문은 지난 통과 기록의 엔진 판과 지금 판이 다르면 그림이 바뀐 장 번호를 알림
- 사람 견본: `scripts/samples.py add 사람.pptx` 로 손으로 만든 잘 된 장의 배치 수치(도형, 글자, 색, 글자 크기, 그림, 연결선 수, 면적)를 유형별(구성도, 표, 차트, 보고)로 쌓고, 관문이 같은 유형 견본 범위를 크게 벗어난 장을 주의로 냄 (`assets/samples.json`, 수치만)
- 사람 판별 시험: `scripts/blind.py make 폴더 --human 사람.pptx --engine 엔진.pptx` → 독립 검토 에이전트가 폴더의 `prompt.md` 대로 `answers.json` 작성 → `blind.py score 폴더` 가 엔진 장을 사람으로 본 비율을 개인 설정 `blind_history.csv` 에 쌓음 (판마다 비교)
- 실패한 과제 빌더는 그 과제 세션에서 고친다

## 10-2b. 만든 덱의 글만 고치기
- `python -P scripts/edit_deck.py 원본.pptx 출력.pptx --replace 장번호 "옛 글" "새 글" [장번호 "옛 글" "새 글" ...]`: 지정한 장의 글(a:t)만 바꾼 사본을 저장하고, 나머지 파트는 바이트 그대로. 끝에 바뀐 장과 안 바뀐 장의 해시 대조를 보고함
- 원본은 읽기만 하고 덮지 않음(python-pptx 로 열지 않음). 옛 글이 없거나 빈 문자열이거나 장번호가 범위 밖이면 저장하지 않음
- 끝나면 `python -P scripts/gate.py --deck 출력.pptx` 를 안내함: 검사, 렌더, 통과 기록은 이 명령으로 (출력 파일 이름도 `제목_작성자_v버전_YYMMDD` 규칙)
- 글상자 크기, 줄 나눔은 그대로라 글이 길어지면 렌더로 확인. 구조를 바꾸려면 build.py 를 고쳐 관문을 다시 돌림

## 10-3. Google Slides 로 보낼 때
- Google Drive 연결(커넥터)이 있으면 pptx 를 올려 Google 프레젠테이션으로 변환, 없으면 사용자가 Drive 에 올려 'Google 프레젠테이션으로 열기'
- Pretendard 는 Slides 에 없을 수 있음(글꼴 대체). 수식 상자는 Slides 에서 한 줄 식(대체 글)으로 보임: 수식이 메시지인 장은 PDF 를 함께 보냄
- 편집 가능한 차트는 Slides 에서 그림으로 바뀜 (숫자 고치기는 PowerPoint 에서)
