# 월간 OKR 작성 규칙

## 1. 이월과 대응
- 당월 계획은 전월 덱의 익월 계획을 그대로 쓴다. 새로 짓지 않는다. 바꿔야 하면 사용자와 상의한다.
- Review 는 계획 항목과 순서를 맞춘다. 계획에 있던 일이 안 됐으면 안 됐다고 쓰고, 근거가 없으면 `【확인 필요】` 를 붙인다.
- 못 한 항목은 익월 계획에 이월 표시(예: `(10월 이월)`)로 다시 올린다.
- 익월 보드의 Review, 달성현황은 비운다.

## 2. Review 형식 (9월 덱 실측)
- 일반 보드: 머리줄 `[KR1-1] <고객사> <과제명> - <차년> 中` 1개 + `-` 글머리 줄. 한 줄 안에 끝낸다 (전각 45자, 영문과 숫자는 폭이 좁아 약 55자). 칸에는 글머리 10개가 들어간다.
- 도전 보드: `라벨: NN% 완료 (근거)` 형식. 라벨(콜론까지)만 굵게. 줄 수는 4개 안팎, 줄마다 2줄까지 괜찮다.
- 계획 항목에 대응하는 줄 하나에는 사실 한두 개만 담는다.

## 3. 숫자
- 모든 숫자에 단위. 수치는 문서나 결과 파일에서 다시 확인한 것만 쓴다. 이전 덱 값을 복사하지 않는다.
- 문서끼리 수치가 다르면 가장 늦게 갱신된 쪽을 쓰고 보고에 충돌을 적는다 (이번 달 사례: 시험 수 1,411, 1,514, 1,554, 학습표 행 수 55,153, 55,228, 56,653, Max 상위 10% 오차 0.272, 0.273).
- 달성현황(%) 제안식: `전월 실적 + (당월 4W 목표 - 전월 실적) x 계획 항목 완료율` 내림. 완료율은 0, 0.5, 1 같이 근거로 설명되는 값만. 최종 숫자는 사용자가 확정한다.
- 도전 보드의 4W 목표는 그 달 안의 진행률이다 (누적이 아님).

## 4. 문장
- 명사형 종결(`완성`, `반영`, `정정`). 가운뎃점, 줄표 사용 안 함, 쉼표나 괄호로 대체.
- 경영진 눈높이로 번역: 파서는 자동 변환 프로그램, 런북은 설치 안내서, 가짜 PLC 는 모의 설비, 온프레미스는 고객사 서버 설치.
- 추측, 기대값, 미확인 원인은 쓰지 않는다. 이유를 모르면 이유를 쓰지 않는다.
- 사업적 의미가 드러나게: 출하 준비 완료, 병목 해소, 재사용 자산 확보.

## 5. Appendix
- 산출물 1개 = 슬라이드 1장. 이미지는 가로 1,600px 이상 (check 가 검사). 웹 화면은 3840x2160으로 찍는다.
- 캡션 `[참고N] 설명`. 번호는 spec 순서대로 자동으로 매겨지고, Review 줄에서 `(참고N)` 으로 가리킬 수 있다.
- 핵심 개요는 3~6줄. 수치는 이미지에 보이는 값이나 근거 문서의 값만. 캡처 날짜와 환경(개발 서버 등)을 마지막 줄에 적는다.
- 개발 PC 경고, 비밀번호, 고객 식별 정보가 보이는 캡처는 쓰지 않는다. 보고 덱 슬라이드를 쓸 때는 제목 띠와 푸터를 잘라 차트만 남기고 출처 쪽수를 적는다.
- 원본 이미지는 작업 폴더의 images/ 에 보존하고 자르기는 spec 의 `crop` ([left, top, right, bottom] px)로 한다.

## 5-1. 임원 보고 기준 (2026-10 사용자 피드백)
- 덱에 `확인 필요` 를 남기지 않는다. 근거가 없는 항목은 쓰지 않고, 대화에서 사용자에게 묻는다.
- 두괄식, 핵심만. 개발자가 알아야 할 내용(시험 개수, 형식 오류 건수, 내부 구조)은 뺀다. 임원이 읽는 숫자만 남긴다 (설비 대수, 개선율, 변환 성공 개수).
- Appendix 는 핵심 산출물 3장 안팎. 수집 항목 관리 화면 같은 세부 화면은 뺀다.
- 사업 방향이 바뀐 항목(예: 동도금 AI Guru 협업 중단, 자체 모델 개발)은 Review 에 전환 사실 한 줄, 익월 계획에 새 방향으로 쓴다. 지난달 계획 칸은 이력이라 그대로 둔다.

## 6. 과거에 겪은 문제
- 9월 템플릿의 일반 보드 1행 "주요결과물" 칸이 왼쪽 정렬이어서 나머지와 어긋났다. build 가 3~8열을 가운데 정렬로 통일한다.
- 달성현황 칸이 비어 있던 템플릿 셀은 글자가 커서(20pt) 값을 넣으면 표가 늘어나 아래 라벨을 가렸다. 4W 칸의 글자 서식을 복제해서 해결했다 (okr_deck.py 에 반영).
- 슬라이드를 PowerPoint 로 열면 보안 솔루션이 파일을 암호화해 python-pptx 가 못 읽는다. 원본과 출력은 열지 않는다.
- 에이전트가 읽은 보고 덱은 이후 수정되어 슬라이드 번호가 밀릴 수 있다. 캡처할 슬라이드는 키워드로 다시 찾는다.
