# interx-deck:okr: 월간 Individual OKR 덱

자유 디자인이 아니라 양식 칸 채우기다. 지난달 덱의 레이아웃과 서식을 그대로 두고 내용만 갈아 끼운다.
필요한 정보는 지난달 덱과 연결된 폴더, 서비스에서 찾는다. 사용자에게는 정말 없는 것만 묻는다.

`S` = `${CLAUDE_PLUGIN_ROOT}/skills/okr/scripts`

| 명령 | 역할 |
|---|---|
| `python -I S/okr_scan.py find <폴더...>` | 폴더에서 OKR 덱을 찾아 최신 월 순으로 |
| `python -I S/okr_scan.py read <지난달 덱> --out pre.json` | 작성자, 이번 달 계획, KR 행, 지난달 실적을 읽어 spec 초안 |
| `python -I S/okr_scan.py evidence <YYYY-MM> <폴더...>` | git 저장소의 그 달 내 커밋, 머지, git 아닌 폴더의 그 달 수정 파일 |
| `python -I S/okr_deck.py build <지난달 덱> <spec.json> <출력.pptx>` | 덱 생성. 행 1~5 자동 증감, 화면 맞춤 |
| `python -I S/okr_deck.py check <출력.pptx> [--style own]` | 검사 (아래 문구 규칙 포함) |
| `powershell -NoProfile -File ${CLAUDE_PLUGIN_ROOT}/scripts/render.ps1 -Pptx <출력> -Out <폴더>` | 확인용 PNG |

## 덱 구조
표지, Vision, Company OKR, **일반 보드 2장, 도전 보드 2장**(당월 일반, 당월 도전, 익월 일반, 익월 도전), Appendix.
- 당월 보드: 계획은 지난달 덱의 익월 계획을 그대로 이월, Review 와 달성현황만 채우고 Review 가리개를 걷는다
- 익월 보드: 지난달 보드를 재활용해 계획만 채운다. Review, 달성현황은 비우고 가리개를 덮는다
- 회사 덱은 양식이 조금씩 다를 수 있다(표지 없이 Vision 부터, 기간 `2026년 Q4_10월`). 빌더는 표 내용으로 보드를 찾는다. 처음 보는 양식이면 build 전에 `read` 로 보드 4장을 제대로 찾는지 본다

## 진행
0. **자료 한 번에 받기** (시작할 때 한 번). 아래 목록을 보여 주고 있는 것만 한 번에 받는다. 대화에 이미 나온 것은 "확인됨" 으로 표시한다
   ```
   이번 달 OKR 에 쓸 자료를 있는 것만 한 번에 알려 주세요.
   1. 지난달 OKR 덱 (파일 또는 폴더, Google Slides 면 PPTX 로 받은 파일)
   2. 이번 달 작업 폴더 (개발 폴더, 문서, 산출물 폴더)
   3. 이번 달 메모 (한 일, 보고서, 회의록)
   4. 보여 줄 산출물 캡처 (Appendix 용, 없어도 됨)
   5. 쓰는 서비스 (캘린더, Jira, Notion, 메일. 안 쓰면 "없음")
   6. 특이 사항 (바뀐 계획, 이관된 일)
   7. 다음 달에 할 일 (큰 덩어리만. 주별로는 알아서 나눔)
   ```
1. **대상 월**: 오늘 기준 이번 달. 1~5일이면 지난달 분으로 보고 그렇게 했다고 알린다
2. **지난달 덱**: 받은 파일 → 없으면 `find` → Drive 연결이 있으면 `title contains 'OKR_Individual'` 검색. 여러 개면 가장 최근 월
   - 디자인은 사용자 본인의 지난달 덱을 그대로 쓴다. build 의 첫 인자는 늘 지난달 덱이다
   - Google Slides 만 있으면 "파일 > 다운로드 > Microsoft PowerPoint" 로 받아 달라고 한 줄 요청한다. 받기 전에는 빌드하지 않는다
   - 덱이 하나도 없는 첫 달: 회사에서 받은 빈 양식을 쓰고, 이때만 Vision, Mission, Company OKR, 작성자를 묻는다. 작성자 기본값은 `~/.claude/interx-deck/profile/profile.json`. 형식은 `references/spec_example.json`
3. **덱에서 읽기**: `read` 로 작성자, 이번 달 계획, KR 행, 지난달 실적
4. **근거 모으기** (있는 것만, 사람마다 출처가 다르다)
   - 대화로 받은 메모, 보고서, 회의록이 먼저
   - 작업 폴더: `evidence YYYY-MM <폴더...>`. `~/.claude/interx-deck/profile/okr/repos.json` 이 있으면 그 경로들도 넣는다. 작성자는 저장소 설정과 덱의 이름으로 자동 판별
   - 연결된 서비스(ToolSearch 로 확인, 없으면 건너뜀)
     - 캘린더: 데모, 시연, 회의 주관 여부는 여기서만 확인된다
     - Jira: `(assignee = currentUser() OR reporter = currentUser()) AND updated >= <월초>`. 상태만 바뀐 옛 티켓이 섞이니 커밋, 문서로 뒷받침되는 것만
   - 커밋 메시지와 파일 시각은 단서다. 수치는 문서, 결과 파일에서 확인한 것만 쓴다. 저장소가 많으면 저장소별로 조사 에이전트를 나눠 돌리고 수치마다 출처를 받는다
5. **spec 작성**: `read` 초안의 `【확인 필요】` 칸을 채운다
   - `current.*.review`: 이번 달 계획 항목 순서대로 한 일. `rows[].ach`: 달성현황. `current.plan` 은 쓰지 않는다 (이월됨)
   - `next`: 익월 `plan` 과 `rows`(1W~4W, 주요결과물). 못 한 계획은 `(N월 이월)` 로 다시 올린다
   - **익월 계획은 알아서 쪼갠다**: 일을 KR 행별로 묶고 → 준비, 설계와 작성, 적용과 검증, 정리와 공유 순으로 나눠 → 1W~4W 에 놓는다 (이월은 앞쪽, 4W 는 마무리). W 칸은 2~3단어 명사형, 주요결과물은 4W 끝에 남는 산출물 이름. 나눈 결과는 보고에서 짧게 보여 주고 고칠 곳만 받는다
   - `appendix`: 기본 `[]`. 요청할 때만 산출물 3장 안팎
6. **빌드 → check → 렌더**: build 가 화면 맞춤을 자동으로 한다 (열 너비 재배분, 간격과 글자 줄이기, 안 들어가면 Plan 과 Review 를 통째로 다음 장으로). 빌드 출력에 `남은 넘침:` 이 있으면 그 문구만 줄여 다시 빌드한다. check 가 PASS 일 때까지 spec 을 고치고, 보드 4장과 Appendix 를 PNG 로 눈으로 본다
7. **보고**: 덱 경로, KR 별 달성현황과 계산 근거, 사용자가 확정할 것(달성현황 %, 익월 주별 목표, 근거를 못 찾은 항목) 순으로 짧게. 확정 전이라도 덱은 만들어 두고 고칠 곳만 묻는다
   - 파일 이름은 지난달 덱 이름의 월만 바꾼다. 원본은 덮어쓰지 않는다

## 문구 규칙
> 사용자의 지난 덱 문체가 기준이다. 지난 2~3개월 덱을 읽고 머리말, 상태 표시, 상세도, 달성현황을 채우는지를 따른다. 실적에 "(진행)", "(이월)" 같은 상태 표시를 쓰는 문체면 `check --style own`.

| 규칙 | 비고 |
|---|---|
| 확인된 사실만. 근거 없는 항목은 덱에 쓰지 않고 보고에서 묻는다 | 기준선과 비슷한 결과는 "기준선 수준". 덱에 `확인 필요` 를 남기지 않는다 (check 가 잡음) |
| 근거가 없다고 미완으로 판단하지 않는다 | 메일, 대면으로 끝낸 일은 파일에 안 남는다. 했는지 묻는다 |
| 실적(Review)에는 한 일만. 미실시, 미착수, 보류, 연기, 이월 금지 | 못 한 계획은 익월 계획에 `(N월 이월)`. check 가 잡음 |
| 티켓 번호를 어디에도 쓰지 않는다 | 프로젝트키-번호, `(-514)`, `P1-13`. check 가 잡음 |
| 커밋 메시지, 파일 경로, 내부 구조(시험 개수, 포트, 클래스명)를 옮기지 않는다 | 팀 밖 사람이 읽는 업무 언어로. 파서 → 자동 변환 프로그램 |
| 두괄식, 명사형 종결, 사업적 의미가 드러나게 | 출하 준비 완료, 병목 해소, 재사용 자산 확보 |
| 일반 보드 Review: `[과제 묶음]` 머리줄 + `-` 줄, 한 줄 안(전각 약 45자), 10줄 안팎 | check 가 한 줄 넘침을 잡는다 |
| 도전 보드 Review: `라벨: NN% 완료 (근거)` 4줄 안팎 | 라벨만 굵게 (템플릿 서식) |
| 달성현황: 지난달 덱 형식을 따른다(% 또는 "달성, 요지"), 16자 이내 | % 제안식: `전월 실적 + (당월 4W 목표 - 전월 실적) x 계획 완료율(0, 0.5, 1)` 내림. 최종은 사용자 확정 |
| 1W~4W 칸은 좁다 (약 42pt) | 한 칸 2~3단어. 도전 보드 4W 목표는 그 달 안의 진행률 |
| 숫자엔 단위. 문서끼리 다르면 최신 값 + 보고에 충돌 언급 | 이전 덱 값을 복사하지 않는다 |
| 익월 Review, 달성현황, 지난 분기 칸, 이미 상신된 과거 월은 비운다 | 소급 날조 금지 |
| 다른 사람의 일로 보이는 것은 뺀다 | |

자세한 문장, 숫자 규칙과 과거 실수는 `references/writing_rules.md`.

## Appendix
- 산출물 1개 = 1장, 캡션 `[참고N] 설명` (번호 자동, Review 에서 `(참고N)` 으로 가리킴). 이미지 가로 1,600px 이상 (check)
- 웹 화면은 Playwright 로 3840x2160, 보고 덱 장은 render.ps1 로 렌더해 필요한 부분만 spec `crop` 으로 자른다
- 핵심 개요 3줄 안팎: 이미지에 보이는 값이나 근거 문서 값만, 캡처 날짜와 환경
- 비밀번호, 고객 식별 정보, 내부 접속 주소, 개발 환경 경고 배너가 보이면 쓰지 않는다

## 주의
- PowerPoint 로 연 파일은 회사 DRM 이 암호화한다. 원본과 출력은 python-pptx 로만 다루고, 확인은 render.ps1 이 만드는 사본 렌더로 한다
- build 의 실측 맞춤도 render.ps1 로 사본을 PDF 로 만들어 잰다 (pdfplumber 가 없으면 건너뜀)
- 다른 세션이 작업 중인 저장소는 대신 커밋하지 않는다. 오래 커밋 안 된 변경, 원격 없는 저장소는 보고만 한다
- 일반 장표 규칙은 적용하지 않는다. 양식 서식을 그대로 따른다
