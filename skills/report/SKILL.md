# interx-deck:report: 보고 자료

공통 규칙(작성자 묻기, 덱 구성, 제목, 글쓰기, 관문)은 `interx-deck:using`. 엔진 `${CLAUDE_PLUGIN_ROOT}/scripts/ixdeck.py`, 출발 파일 `scripts/example_build.py`.

## 0. 쓰임새 고르기 (내용 정하기 전에)
요청에 드러나지 않으면 AskUserQuestion 으로 한 번 묻는다. 쓰임새가 구성, 정보량, 공개 범위를 정한다. 색과 양식은 같다.

| | 사내보고 | 회의 발표 | 고객 | 파트너 | 문서 배포 |
|---|---|---|---|---|---|
| 목적 | 판단 받기 | 이해, 공감 | 신뢰, 다음 단계 | 우리 기준대로 만들게 하기 | 기록, 참조 |
| 독자 | 맥락을 아는 팀장, 임원 | 주제를 모르는 사내 사람 | 회사 밖 고객 | 함께 구축하는 협력사 | 나중에 찾아볼 누구나 |
| 첫 본문 장 | 보고 요약 (현황, 이슈, 요청) | 왜 필요한가 (문제 사례) | 고객의 과제 | 협업 흐름 | 문서 정보 |
| 정보량 | 핵심만, 상세는 Appendix | 핵심 3개 정도 | 원칙만 | 지킬 규칙 전부 | 전부, 원문 그대로 |
| 서술 | 결론, 요청 먼저, 수치 근거 | 쉬운 말, 예시 하나 | 고객 관점 | 규칙 + 좋은 예, 나쁜 예 | 중립, 조건 문구 그대로 |
| 내부 정보 | 그대로 | 내부 ID, 약어는 쉬운 말로 | 공개 승인분만 | NDA 범위, 내부 구현 빼기 | 그대로, 미확정 포함 |
| 마지막 본문 | 다음 단계, 기한, 담당 | 일정, 문의처 | 도입 절차, 문의 | 변경 관리, 연락 창구 | 확정 필요 사항, 변경 이력 |

- **사내보고**: 결정 요청은 선택지 A/B, 제안(안), 이유, 결정되면 시작되는 일, 기한. 모르는 일정, 담당은 지어내지 않고 사용자에게 묻는다
- **회의 발표**: 전문 용어는 처음 나올 때 한 줄로 풀고, 예시는 '예시' 라고 밝힌다
- **고객, 파트너**: 덱에 나가면 안 되는 말을 `Deck(..., forbid=[정규식])` 에 넣는다. 저장이 찾으면 멈춘다
  - 넣을 것: 내부 ID 형식, 팀명, 내부 수치, 구현 용어, 사설 IP(`192\.168\.`, `10\.\d+\.`), `localhost`
  - 외부에 나가기 전 기밀, 개인정보 확인을 사용자에게 한 줄로 상기
- **문서 배포**: 요약, 설득 금지. 항목 전부를 표로, 미확정 사항과 변경 이력을 각각 한 장. 개인 이름은 역할, 팀으로

## 1. 보고형 장
```python
s = d.page("핵심 수치 (예시 값)", lead="요약 한 줄")
top = banner(s, "핵심 문장 한 줄", tags=["1단계", "2단계", "3단계"], current=1)   # 없어도 됨
a, b, c = cols = report_panels(s, ["원천", "규칙", "결과"], top=top, footnote="* LLM: Large Language Model")
a.table(rows, ratio=[1.2, 2]).notes(["결론"])
b.rule_list("규칙", [("doc_check", "이름", "설명"), ...])
c.chart("col", 항목, {"건수": 값}, highlight=(1,))
for col in cols: col.done()       # 모든 패널에 블록을 넣은 뒤 (장 전체 상자 높이 맞춤)
```
| 블록 (Col) | 모양 | 출처 |
|---|---|---|
| `table(rows, ratio, highlight=)` | 회색 머리행 표, 강조 행은 남색 글 | 템플릿 2장, 참고 덱 협조 요청 |
| `rule_list(제목, [(아이콘, 이름, 설명)])` | 가는 테두리, 아이콘, 굵은 이름과 설명 | 템플릿 2장 |
| `section(제목, 줄들)` | 회색 머리 띠 목록 | 템플릿 3장 |
| `tab_box(이름표, 줄들)` | 연회색 테두리 묶음, 왼쪽 위 남색 네모 이름표. 이름표는 명사 | 참고 덱 '1단계 지금' |
| `num_cards([(제목, 설명)])` | 회색 테두리 카드마다 남색 번호, 제목, 설명 | 참고 덱 'MES 우선 DB' |
| `chevrons(단계들, current=)` | 단계 화살표 줄, 지금 단계 남색 | 참고 덱 단계 로드맵 |
| `kpis([(값, 단위, 이름)])` | 상자 없는 큰 남색 숫자와 회색 이름 | 참고 덱 '80+ Recipe_AI' |
| `formula(식, where=[정의], name=)` | 논문식 수식 (PowerPoint 수식 개체), 기호 정의와 단위 | |
| `chart(kind, 항목, {계열: 값})` | 편집 가능한 차트 col, bar, stack, line | |
| `gantt(기간, 일들, today=)` | 일정 막대 | |
| `image(그림, h, marks=)` + 옆 패널 `steps` | 화면 캡처와 번호 설명 | |
| `scatter({계열: [(x, y)]}, 'x 이름 (단위)', 'y 이름 (단위)')` | 편집 가능한 산점도 (축은 데이터 범위, 축 이름 필수) | |
| `hist(값들, 경계들, highlight=)` | 편집 가능한 히스토그램 (구간별 건수 세로 막대) | |
| `mpl_style()` 뒤 matplotlib 그림을 `image` | 편집 가능한 차트로 못 그리는 분석 그래프만 (덱 색). 기본 주황과 파랑 그림은 저장이 잡음 | |
| `icon_cards`, `box`, `arrow`, `notes` | 원천 아이콘 줄, 상자, 아래 화살표, '※' 메모 줄 | 템플릿 2장 |
- `done()` 이 패널 높이에 맞춰 블록을 나눈다. 남는 높이는 표 행, 목록 줄, 번호 사이, 차트가 먼저 받고 그다음 블록 사이. 보이는 빈 곳 0.5 in 넘으면 저장이 멈춤. 그 장의 사실로 블록을 더하고 지어내지 않는다
- **같은 장 같은 종류 상자는 같은 높이**(번호 카드, 번호 설명, 이름표 묶음, 규칙 목록 줄), 제목과 설명은 한 덩어리로 상자 가운데, 번호 원 0.18 in 8pt
- **핵심 수치 줄(`kpis`)은 숫자가 그 장의 메시지일 때만. 한 장에 한 줄, 덱 본문 장의 1/5 까지**
- 패널 사이: 기본은 화살표 없음. 앞 패널의 결과가 다음 패널로 넘어갈 때만 `arrows=True`, 넘어가는 것을 보이려면 `steps=[("badge_aas_server", "AASX 해석"), ...]`
- 패널 틀: 머리 위 1.86(띠가 있으면 그 아래), 몸통 아래 6.915(꼬리말 선 7.215 위 0.30), 좌우 0.29 ~ 13.09. 3열은 기본 너비 3.94 / 3.21 / 3.60
- 점선 다발(표 행과 칩 잇기): `report_panels(..., hub_gap=1)` 뒤 `bundle(s, row_anchors(s, b[0]), 칩들, cols.gaps[1], "이름")`

## 2. 화면 캡처 장
- `Col.image(그림, h, marks=[(x0, y0, x1, y1, 번호), ...])` 비율은 그림에 5% 격자를 그려 잰다. 옆 패널 `steps([(번호, 제목, 설명)])`
- 영역 빨간 네모, 번호는 왼쪽 위 모서리, 가까운 변은 맞춰 같은 열 네모는 같은 폭(자동). 번호가 겹치면 저장이 멈춤
- 캡처는 요소 단위로 찍어 잘림이 없게. 제3자에게 가는 자료는 고객 식별자(제품, Tool, Lot 번호)를 가림. 고객 자신이 보는 자료는 가리지 않음

## 3. 고객사(수요사) 보고 구성
- 순서: 과제 개요 → 접근 방향(왜 이 범위인가) → 데이터(원천 명세, 사용과 미사용 이유) → 연구와 발견 → 입력과 출력 정의 → 시험 결과와 벤치마크 → 화면 → 다음 단계 → Appendix(예상 질문과 답)
- 넣지 않는 것: 개발자, 모델링 담당자만 알 내용(알고리즘 이름, 하이퍼파라미터, 배포, 도커, QA 문서), 다른 회사나 담당자 비교, 내부 시행착오
- 설명보다 그림: 한 장은 도식 하나나 차트 하나가 중심, 글은 짧은 문구와 아래 한두 줄. 긴 표는 명세가 필요한 장에만
- 본문 20장 이내(Appendix 제외), 결론 장을 먼저
- 숫자: 모든 숫자에 단위, 축과 값 라벨에도 단위. 제조 현장 전문가 대상이면 mm 는 소수 둘째 자리
- 실제값과 예시: 실제 데이터에는 꼬리표를 붙이지 않고 조건(대상 개수, 기간, 측정 기준)을 각주로. 예시 값이면 '예시' 를 반드시 표시
- 사용하지 않은 데이터는 이유를 사실로(예측 시점에 없는 값, 기간 부족, 효과 미확인)
- 통계 용어(MAE, R², AUC, 기준선)를 쓰면 결과 장 아래 한 줄 풀이와 Appendix '용어 설명' 표
- 입력과 출력은 명세 표(이름, 의미, 단위, 원천)와 도식으로
- **Appendix 예상 질문과 답**: 상대가 가질 법한 반론 위주(이전 경험, 범위에 대한 의문). 답은 사실, 수치, 대응, 확인 필요 사항 순

## 4. 성능 자료와 한계
- 성능 표: 출력마다 검증 방법, 시험 개수, 오차(MAE, RMSE, 편향), 기준선과의 차이와 95% 구간, 판정
- 오차는 실제 값 크기와 허용 기준(판정 기준 높이)을 나란히. 큰 오차는 크다고 인정하고 대응을 적음
- 벤치마크: 기준선, 이전 모델, 유사 과거 설계 평균. 알고리즘 비교와 선정 규칙, 계산식과 구현 정합성 검수 결과(재계산 대조 건수, 불일치 건수)
- **한계 표**: 한계 / 의미 / 근거 수치 / 대응 네 열. '차이 확인 안 됨' 같은 말은 의미(95% 구간이 0 포함)를 같이
- 지표, 계산식은 `formula(r"J_{보정} = J_{0} \times \frac{A}{B + \hat{d}}", where=["J_{0}: 뜻 (단위)", ...], name="식 이름")`.
  표기: `_{}` 아래첨자, `^{}` 위첨자, `\frac{}{}`, `\hat{}`, `\bar{}`, `\text{}`, `\times`, `\pm`, `\le`, `\Delta`, `\sum`. 한 글자 라틴 기호만 기울임, 두 글자 이상과 한글은 바로 세움.
  직접 만든 식이면 그 사실과 도출 근거

## 5. 일정과 비교
- 일정: `Col.gantt(...)` 막대 색은 끝남 회색, 진행 남색, 예정 남회색, 마름모 마일스톤, 빨간 점선 오늘. 단계는 `chevrons`
- 현행 vs 개선: `report_panels(s, ["현행", "개선"], widths=(5.9, 5.9))`, 표 `highlight` 로 바뀐 행 남색
