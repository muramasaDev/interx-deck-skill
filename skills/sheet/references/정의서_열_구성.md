# 정의서 권장 열 구성

- 용도: 정의서 종류별 시트와 열을 어떻게 나눌지 정하는 기준. 용어는 공공기관 DB 표준화 지침(엔터티, 속성, 테이블, 컬럼 정의서)의 논리명 및 물리명 구분을 따름. 지침 원문은 확인하지 못했으므로 열 이름은 권장이며 발주처 양식이 있으면 그 양식이 우선
- 공통: 첫 열은 ID, 한 칸에 한 값, 여러 값은 ID 로 연결한 하위 표로 나눔 (하위 표 첫 열은 `Field("테이블 ID", "ref")`, 둘째 열은 순번 또는 코드), 빈 칸은 `-`, 문서 정보 및 개정 이력 시트가 맨 앞

## 1. 테이블 정의서
| 시트 | 열 |
|---|---|
| 테이블 목록 | 테이블 ID, 테이블명(물리), 테이블명(논리), 설명, 저장소, 필드 수, 비고 |
| 필드 목록 | 테이블 ID, 순번, 컬럼명(물리), 컬럼명(논리), 데이터 타입, 길이, 필수, 키, 기본값, 설명 |
- 키 칸은 PK, FK, UK 중 하나(복합이면 행을 나눔), 필수는 `필수` 또는 `선택`
- 문서 저장소(JSON 설정 파일 등)는 컬럼 대신 키 이름과 값 형식을 같은 열 구성으로 적음

## 2. API 정의서
| 시트 | 열 |
|---|---|
| API 목록 | API ID, 구분, API 이름, Method, URL, 인증, 호출 주기, 상태, 관련 기능 ID |
| API 파라미터 | API ID, 순번, 구분(요청 또는 응답), 위치(경로, 쿼리, 본문, 헤더), 항목, 형식, 필수, 설명 |
| 오류 코드 | API ID, 코드, 조건, 메시지 |
- 요청과 응답을 한 칸에 이어 쓰지 않고 파라미터 시트로 나눔 (파라미터별로 거르고 정렬)

## 3. 개발 기능 항목 정의서
| 시트 | 열 |
|---|---|
| 기능 목록 | 기능 ID, 기능명, 설명, 담당 역할, 연동 시스템, 우선순위, 상태, 진척률, 근거, 요구사항 ID, API ID |
| 집계 | 시스템별 항목 수 및 상태별 건수 (엔진이 수식 셀을 막으므로 값을 계산해 넣음) |
- 상태는 상태 칸 규칙(완료, 진행, 계획, 미정), 진척률은 숫자 칸(%)

## 4. 화면 정의서
| 시트 | 열 |
|---|---|
| 화면 목록 | 화면 ID, 화면명, 메뉴 경로, 설명, 관련 기능 ID, 관련 API ID |
| 화면 요소 | 화면 ID, 번호, 요소, 동작, 검증 및 표시 |
- 요소 번호는 설계서 캡처의 번호 원과 같은 수

## 5. 추적 매트릭스
- `matrix()` 로 행은 기능 ID, 열은 요구사항 ID 또는 API ID, 연결은 `●`
- 감리는 요구사항, 기능, API, 화면, 테이블이 ID 로 이어지는지(추적성)를 봄
