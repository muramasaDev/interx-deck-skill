# 구성도 읽힘 규칙

- 용도: 구성도를 보는 사람이 무엇이 어디에 들어 있고, 값이 어디서 와서 어디로 가며, 어떤 기능인지 한눈에 알게 하는 규칙
- 막으려는 결함: 제품 이름 띠가 하위 기능을 감싸지 않음, 처리 상자의 원천이 그려지지 않음, 기능 구분이 없음, 화살표 뜻이 불분명함
- 예제: `scripts/example_diagram.py` (배치도, 기능과 배치 대응표, 처리 순서). 복사해서 내용만 바꿈

## 1. 한 그림은 한 질문에 답함
| 그림 | 답하는 질문 | 엔진 |
|---|---|---|
| 배치도 | 무엇이 어디(현장, 에지 장치, 서버)에 있고 값이 어디서 어디로 가나 | `DocGrid`, `link`, `fan` |
| 기능과 배치 대응표 | 기능 묶음마다 어떤 모듈이 있고 어디서 실행되며 받는 값과 내보내는 값은 | `Col.table` (기능 묶음, 모듈, 위치, 받는 값, 내보내는 값) |
| 처리 순서 | 한 사건이 어떤 순서로 처리되나 | `mermaid` sequenceDiagram |
| 사용자 흐름 | 사용자가 목표까지 어떤 화면을 거치나 | `mermaid` flowchart 또는 `chevrons` |
- 한 그림에 두 질문을 섞지 않음: 배치도에는 처리 번호만 두고 상세 순서는 처리 순서 그림으로

## 2. 포함 관계가 보여야 함
- 위치 묶음(EdgePC, 서버) > 제품 또는 프로그램 이름 > 기능 묶음 > 모듈 순으로 안쪽에 담고 네 단을 넘기지 않음
- 제품 이름 띠(`header=`)는 하위 기능 묶음을 감싸는 영역과 한 덩어리: `g.group(..., header="이름", area=True)`
- `area=False` 에 `header` 만 두면 이름 띠가 영역 위에 떠서 하위 묶음이 그 안에 있는지 알 수 없음 (저장 때 주의)

## 3. 값의 원천과 도착이 보여야 함
- 모든 처리 상자는 들어오는 선과 나가는 선이 모두 있음. 원천은 나가는 선만, 도착은 들어오는 선만
- 상자를 만들 때 `flow="source"`(내보내기만), `"sink"`(받기만), `"process"`(받아서 내보냄) 를 적으면 저장 때 선이 빠졌는지 알려 줌
- 현황, 알림처럼 값을 만들어 내보내는 모듈도 그 값의 원천 모듈에서 선이 와야 함 (예: 수집 코어에서 현황 보고로)

## 4. 화살표 뜻
- 머리는 값이나 요청이 가는 방향. 양방향 머리(`head="both"`)는 요청과 응답 쌍이나 보관 후 다시 전송처럼 오가는 것에만
- 선 모양과 색마다 의미를 정하고 범례 한 줄: 굵은 남색 실선은 주 데이터 흐름, 점선은 계획 및 설정 전달, 가는 회색은 현황 및 알림, 점 점선은 실패 시 보관, 빨강은 끊김
- 번호 원은 시간 순서이고 같은 번호는 한 처리. 선 색은 의미 셋까지 (넷부터 주의)
- 번호 원은 선 위에 얹히고 짧은 글이 바로 붙음: 어느 선의 번호인지 모호하면 안 됨. 선 위에 못 놓으면(선이 짧거나 주변이 막힘) 주의, 번호 대신 선 이름(`text=`)
- 상자 이름은 '대상 + 동작' (`수집 항목 및 주기 제공`), 대상이 빠진 `수집 계획 제공` 은 저장 때 주의. 줄일 수 없으면 `abbr_legend` 로 용어 풀이

## 5. 색은 뜻으로 고정
- 기능 묶음 색 `TONES`: `collect` 수집(파랑), `send` 전송(청록), `manage` 관리(보라), `store` 저장(남회색), `report` 현황 및 알림(황갈색). 머리띠와 옅은 바탕을 같은 계열로: `g.group(..., tone="collect")`, `sub(..., tone=)`
- 한 장에 기능 색은 넷 이하이고 `legend(s, x, y, [(TONES[k][0], "수집 기능")], kind="square")` 로 범례
- 상자 역할 색(`role_box`): 회색은 기존, 초록은 AI, 노랑은 확장, 남색은 핵심 서버
- 색은 구분용: 장식으로 바꾸거나 같은 색을 다른 뜻에 쓰지 않음

## 6. 그리기 전 점검표
1. 이 그림이 답하는 질문 한 줄
2. 가장 바깥 묶음부터 안쪽까지 포함 관계 (제품 이름이 하위 기능을 감싸는가)
3. 모든 상자의 원천과 도착 (선이 하나뿐인 처리 상자는 없는가)
4. 화살표 방향과 선 모양의 뜻 (범례가 있는가)
5. 기능 색이 기능 묶음과 일치하고 범례가 있는가
6. 번호가 선 위에 얹혔는가, 이름에 대상이 있는가 (종류별 계층 점검은 `구성도_종류_고르기.md` 4장)
