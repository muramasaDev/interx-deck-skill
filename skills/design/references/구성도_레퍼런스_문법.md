# 구성도 레퍼런스 문법

- 용도: 시스템 구성도, 아키텍처도, 단계 흐름도를 그릴 때 따를 사람이 만든 덱의 공통 문법. 특정 회사나 제품의 그림이 아니라 반복해서 보이는 규칙만 정리
- 색 값은 캡처를 눈으로 본 추정치이고 엔진 상수(NAVY, SLATE6, SLATE3, ACCENT 등)가 우선

## 1. 상자 위계 (4단)
| 단 | 모양 | 쓰임 |
|---|---|---|
| 1 | 짙은 남색 제목띠 + 흰 글자 | 플랫폼, 시스템 묶음 |
| 2 | 연한 회색 바탕 컨테이너, 가는 테두리 | 묶음 안쪽 영역 |
| 3 | 회색 소제목 띠 + 검정 글자 | 서버, 모듈 묶음 |
| 4 | 칩 (한 줄 이름 + 작은 영문 부제) | 개별 모듈, 서비스 |
- 위계는 테두리를 겹치는 대신 색 단계로 만듦 (테두리는 가는 한 겹)

## 2. 의미가 고정된 칩 색 (범례 없이 읽히게)
| 색 | 뜻 |
|---|---|
| 중간 회색 (SLATE6) | 기존, 일반 모듈 |
| 초록 | AI, 에이전트 |
| 노랑 | 확장 항목: `Additional ...` 칩, `...` 줄임표, 아래 `신규 ○○ 동적 추가` 문구와 짝 |
| 짙은 남색 | 플랫폼, 핵심 서버 |
- 한 장 안에서 색의 뜻을 바꾸지 않음. 칩 색이 셋을 넘으면 뜻을 다시 정함

## 3. 화살표와 선
- 큰 흐름(학습 데이터 제공, 배포): 그라데이션 블록 화살표(남색에서 옅게) + 위에 굵은 라벨. 세부 연결은 가는 선
- 선 색은 의미 셋까지: 데이터(파랑), 제어(빨강), 공통 버스(굵은 회색). 엔진은 넷부터 주의를 냄. 색마다 범례 한 줄
- 번호 원(빨강 또는 남색) + 같은 줄 라벨로 순서를 표시 (엔진 `step_badge`, `num_badge`)
- 연결선 위 작은 알약 태그로 프로토콜을 표시 (예: 약어 두세 글자, 초록 채움)

## 4. 로고와 캡처
- 기술 로고는 흰 카드, 얇은 테두리, 로고만 (카드 안 글자 없음)
- 화면 캡처는 변환 전 및 후를 나란히 놓고 주황 화살표로 이음. 캡처 뒤에 연한 쉐브론 배경을 깔면 단계가 읽힘
- 캡처 위 강조는 얇은 박스와 번호 원

## 5. 장 구성
- 단계형: 쉐브론 머리띠가 가로로 이어지고 열마다 하나의 단계. 아래에 열과 같은 폭의 둥근 요약바에 단계별 한 줄
- 헤드라인 두 줄: 핵심 키워드만 색(초록, 파랑)으로 강조
- 문제 제기: 현업 말투 한두 문장을 말풍선으로 (이모지는 쓰지 않음)
- 구성도 아래: 약어 풀이 한 줄(`MCP : ...`)과 핵심 요약 불릿 3줄

## 6. 엔진 반영 상태
- 반영: 연결선 색 의미 셋 허용, 번호 원, 로고 카드, 두 색 아이콘, 쉐브론
- `ixdiag.py` (엔진이 같은 이름공간에 불러옴): `role_box(s, x, y, w, h, 글, role="base|ai|ext|platform", sub=)` 역할 색 칩, `block_arrow(s, x, y, w, h, label=, direction=)` 그라데이션 블록 화살표, `pill(s, x, y, "MQTT")` 프로토콜 알약, `abbr_legend(s, x, y, w, bullets=, abbrs=)` 하단 요약 및 약어 풀이
- 단계형 장: `step_header(s, x, y, w, 단계 글 목록)` 남색 쉐브론 머리띠 (열 위치 [(x, 너비)] 를 돌려줌), `summary_bar(s, cols, 열별 한 줄, y)` 둥근 요약바, `speech_bubble(s, x, y, w, h, 글, tail=)` 말풍선
- `headline(s, x, y, w, [[(글, 강조 여부), ...], ...])` 가운데 맞춤 두 줄 헤드라인의 키워드 색 강조, `backdrop(s, cols, y, h)` 캡처 뒤 연한 쉐브론 배경 (캡처보다 먼저 그림)
