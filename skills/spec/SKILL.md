# ixdeck:spec: AI 학습데이터 명세서 HTML

엔진 `${CLAUDE_PLUGIN_ROOT}/scripts/ixspec.py`, 출발점 `scripts/example_spec.py`, 브라우저 검증 `scripts/spec_verify.py`. 작성 순서와 칸 규칙은 `references/명세서_작성_순서.md`, 저장 데이터 구조와 양식이 검사하지 않는 곳은 `references/양식_데이터_구조.md` (필요한 장만 Grep 으로 읽음).

## 왜 이 도구가 필요한가
- 양식 HTML 은 저장 때 필수 항목을 검사하지 않고, 불러올 때 없는 D#, S# 참조와 쉼표 든 숫자, 허용 밖 이미지를 조용히 지움. 빠진 줄 모른 채 제출하는 일이 생김
- 그래서 (1) 양식의 선택 목록으로 미리 점검, (2) 채운 파일을 브라우저에서 열어 양식의 저장으로 되돌려 비교

## 순서
1. **준비**: 사용자가 받은 `AI학습데이터명세서_기관별작성양식.html`(작성용, 취합용은 `취합및제출양식.html`)과 작성 대상과제 list 의 경로를 받음. 이 저장소에는 양식 파일이 없음. 양식 판이 2.0 이 아니면 알림
2. **질문 (AskUserQuestion 한 번)**: 작성용(기관 하나) 또는 취합용(주관기관 최종 제출), 새로 작성 또는 기제출 갱신, 기관명과 소재 지역, 대상 모델 목록. 취합용이면 과제명, 과제번호, 주관기관, 작성자
3. **사실 수집**: 과제 자료(인계 문서, 데이터 사양서, 코드와 데이터 목록)만 읽음. 읽을 파일을 정하고 Explore(model: haiku) 로 훑음. **모르는 값은 비우고 지어내지 않음**. 건수, 용량, 기간, 설비 사양은 원천 자료에서만
4. **작성**: `example_spec.py` 를 `build.py` 로 복사해 내용만 교체. `Spec` > `model` > `target`, `step`, `equipment`, `device`, `dataset`, `prep_step`, `io`, `split`, `ai`. 메서드가 돌려주는 ID(T#, P#, E#, S#, D#)를 다음 단계에 넘김
5. **점검**: `sp.save(양식, 출력 폴더)` 가 점검하고 오류가 있으면 저장하지 않음. 주의는 사용자에게 보고. 업종이 목록에 없으면(예: PCB 는 목록에 전용 업종이 없음) 어떤 업종 및 공정으로 둘지 사용자에게 묻고, 직접 입력(custom)으로 둘 수도 있음
6. **브라우저 검증**: `python -P spec_verify.py 파일.html --shots 폴더` 가 통과해야 함 (값이 바뀌거나 사라지면 실패). 화면 캡처(home.png, model1.png)를 눈으로 확인
7. **인계**: 파일 경로, 모델별 점검 결과, 확인 필요 목록(비워 둔 값과 이유)을 알림. 제공동의서는 별도 서식이라 이 스킬이 다루지 않음. 제출 전 사람이 모델별로 화면에서 한 번 훑도록 안내 (제출은 사용자 몫)

## 쓰기 규칙
- 선택 목록 값은 양식 원문 그대로 (가운뎃점이 들어 있어도 바꾸지 않음). 학습 방식(AI Task)은 `이미지 > 영역 분할 (시맨틱)` 처럼 `유형 > 이름`
- 숫자 칸은 숫자만 (건수 정수, 용량 MB), 쉼표와 단위 문자 금지: 빌더가 ValueError 로 막음
- 자유 글(문제 개요, 설명)은 사내 글쓰기 규칙: 가운뎃점과 긴 줄표 금지, 개조식, 추측과 기대 효과 서술 금지(기대 효과 칸은 양식이 요구하는 사실 기준 개선점만)
- 서식 있는 글 칸(문제 개요, 기대 효과, 기타)은 `rich()` 가 문단은 div, `- ` 줄은 글머리표로 바꿈
- 이미지는 `image(경로, 설명)` 로 넣음 (긴 변 1280px, JPEG). 허용 밖 형식은 양식이 지움

## 하지 않는 것
- 제출과 메일 회신 (사용자가 직접)
- 양식 HTML 을 저장소에 넣거나 고치는 것 (form-data 블록만 바꿈)
- 값을 추정해 채우는 것
