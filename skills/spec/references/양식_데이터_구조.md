# AI 학습데이터 명세서 양식 2.0: 데이터 구조와 검증 규칙 (참고용, 빌더 `ixspec.py` 가 이 규칙을 코드로 가짐)

- 대상: `AI학습데이터명세서_기관별작성양식.html` (FORM_VERSION '2.0', APP_MODE 'writer')
- 근거: 양식 스크립트 전체(form.js 1462줄), 빈 양식 HTML, 철강 샘플 A사 HTML의 form-data JSON. 스크립트는 빈 양식 HTML의 `<script>` 블록과 바이트 단위로 같음을 확인함
- 표기: 코드에서 확인된 것만 기재. 확인되지 않은 것은 "코드에서 확인 못 함"으로 표시
- 값 표기: 선택 목록 값은 원문 그대로 입력해야 하므로 가운뎃점이 들어 있는 값은 코드 서식(백틱) 안에만 적음

## 0. 먼저 알아둘 사실

| 번호 | 사실 | 근거 |
|---|---|---|
| 1 | 양식 스크립트에는 저장 또는 제출 때 필수 항목을 검사해 막는 코드가 없음. `save()`는 검사 없이 `serialize()` 후 파일로 씀 | `save`, `serialize` |
| 2 | 별표(*)는 화면 표시일 뿐이며 저장을 막지 않음. 막는 곳은 각 "추가" 단추의 입력 조건, 숫자 칸의 숫자 필터, 불러오기 때 `normalize` 정리뿐임 | `fld`, `addTarget`, `numIn`, `normalize` |
| 3 | "제출" 기능은 없음. 내보내기(PDF, JSON, Markdown)만 있음. 제출 파일은 저장한 HTML이며, 주석에 "플랫폼은 이 블록만 읽어 처리합니다"라고만 적혀 있음 | form-data 위 HTML 주석 |
| 4 | 플랫폼 쪽 제출 검증 규칙은 코드에서 확인 못 함. 이 문서의 필수 항목(3장)은 화면의 별표와 추가 단추 조건 기준 | - |
| 5 | 불러오기 정리(`normalize`)는 일부 값만 고치거나 지우고 대부분은 검사 없이 그대로 둠. 목록에 없는 업종, 지역, 장치 종류 등도 지워지지 않음 | 4장, 5장 |

## 1. 저장 JSON 최상위 구조 (form-data 블록)

`blankState()` 기본값과 샘플 저장 결과 기준.

| 키 | 화면 이름 | 형식 | 기본값 | 설명 |
|---|---|---|---|---|
| formVersion | (없음) | 문자열 | `"2.0"` | 저장 때마다 `FORM_VERSION`으로 덮어씀. 불러올 때 검사하지 않음 |
| savedAt | 상단 "저장됨 HH:MM" | ISO 8601 문자열 또는 null | null | 저장(`serialize()`) 때 `new Date().toISOString()`으로 기록 |
| modifiedAt | (없음) | ISO 문자열 또는 null | null | 화면에서 값이 바뀔 때(`changed()`)마다 갱신. 샘플 저장본은 null. 임시 저장 복구 비교에 쓰임 |
| role | 상단 "작성" 표시 | 문자열 | `""` | 로드 후와 저장 때 `APP_MODE`('writer')로 강제 덮어씀 |
| writerOrg | 기본 정보 > 기관명 * | 문자열 | `""` | 저장 때 `syncOrg()`가 모든 모델의 org에 복사함 |
| writerRegion | 기본 정보 > 작성 기관 소재 지역 * | 문자열 (REGIONS 값) | `""` | 모든 모델의 orgRegion에 복사됨 |
| project | (작성용 화면에는 입력란 없음) | 객체 | 아래 | 취합용에서만 입력. 작성용 샘플은 `{}` |
| project.title | 과제명 | 문자열 | `""` | 취합용 필수 표시 |
| project.number | 과제번호 | 문자열 | `""` | 파일명에 쓰임. 취합용 필수 표시 |
| project.leadOrg | 주관기관 | 문자열 | `""` | 취합용 필수 표시 |
| project.author | 작성자 | 문자열 | `""` | 취합용 필수 표시 |
| project.contact | 연락처 | 문자열 | `""` | |
| project.date | 작성일 | 문자열 | `""` | 예) 2026-11-15 |
| models | AI 모델 목록 | 객체 배열 | `[]` | 순서가 화면 번호(#1, #2)이며 id는 1부터 순번 |

- project 하위 키는 `normalize`가 채워 주지 않음. `{}`여도 오류 없이 열림 (샘플이 `{}`)
- 구형 호환: `project.org`가 있으면 `project.leadOrg`로 옮기고 지움
- 불러오기 시작 조건: form-data가 비어 있지 않을 때 `d.role != null` 또는 `d.project`가 참일 때만 `normalize` 후 사용함. 둘 다 없으면 빈 상태로 시작함 (3장 및 8장 참조)
- 파싱 실패 시 `alert('저장된 내용을 읽지 못했습니다. 새 문서로 시작합니다.')` 후 빈 상태로 시작

```json
{"formVersion":"2.0","savedAt":"2026-11-17T04:59:32.929Z","modifiedAt":null,"role":"writer",
 "writerOrg":"A사","writerRegion":"경북 포항","project":{},"models":[ ... ]}
```

## 2. 모델 하나의 구조 (blankModel)

### 2.1 모델 최상위

`blankModel()` 기본값: `{id:0, name:'', org:'', orgRegion:'', problem:{...}, site:{...}, datasets:[], prep:blankPrep(), ready:blankReady(), ai:blankAi(), etc:{note:''}}`

| 키 | 화면 이름 | 형식 | 기본값 | 비고 |
|---|---|---|---|---|
| id | 모델 번호(#) | 정수 | 0 | 작성 화면에서 추가, 삭제 때 1부터 다시 매김. 프로그램 입력 시 1부터 순번 권장 |
| name | (1) AI 모델명 * | 문자열 | `""` | 예) 에칭 공정 최종 불량 예측 모델 |
| org | 담당 기관 | 문자열 | `""` | 저장 때 writerOrg로 덮어써짐 |
| orgRegion | 담당 기관 소재 지역 | 문자열 | `""` | 저장 때 writerRegion으로 덮어써짐 |
| problem | (1) 문제 정의 | 객체 | 2.2 | |
| site | (2) 공정, 설비, 수집 장치 | 객체 | 2.3 | |
| datasets | (3) 원시 데이터 | 배열 | `[]` | 2.4 |
| prep | (4) 전처리 데이터 | 객체 | 2.5 | |
| ready | (5) AI 준비 데이터 | 객체 | 2.6 | |
| ai | (6) AI 모델 | 객체 | 2.7 | |
| etc | (7) 기타 | 객체 | `{note:''}` | 2.8 |

- 샘플의 모델 키 저장 순서: name, org, orgRegion, problem, site, datasets, prep, ai, etc, id, ready (순서 무관)
- 모델 배열 원소가 null 이면 `normalize`에서 예외 발생 (가드 없음)

### 2.2 (1) 문제 정의: model.problem

기본값 `{company:'', companyRegion:'', overview:'', images:[], targets:[], processNote:'', effect:''}`

| 키 | 화면 이름 | 형식 | 비고 |
|---|---|---|---|
| company | 대상 기업 * | 문자열 | 예) ○○제철(주) 포항공장 |
| companyRegion | 대상 기업 소재 지역 * | 문자열 (REGIONS 값) | 부록 B |
| overview | 문제 개요 * | 서식 있는 글(HTML 일부 허용) | 7장 및 2.9 |
| images | 대표 이미지 (선택) | 이미지 객체 배열 | 6장 |
| targets | 대상 업종 및 공정 * (최대 5개) | 객체 배열 | 아래 |
| processNote | 공정 추가 정보 | 서식 있는 글 | 작성 화면에 입력란이 없음. 값이 있으면 읽기 화면, PDF, 내보내기에만 표시됨 |
| effect | 기대 효과 * | 서식 있는 글 | |

targets 원소 (대상 업종 및 공정):

| 키 | 화면 이름 | 형식 | 비고 |
|---|---|---|---|
| id | # (내부 ID) | `T`+정수 | 없으면 `nextId`로 부여. T1, T2 ... |
| industry | 업종 | 문자열 | INDUSTRY 최상위 키 또는 직접 입력 문자열 |
| subIndustry | 세부 구분 | 문자열 | 세부 구분이 없는 업종은 `""` |
| process | 공정 | 문자열 | |
| aiFunction | AI 기능 | 문자열 | AI_FUNCTIONS 중 하나 (직접 입력 없음) |
| custom | (없음) | true 또는 키 없음 | 업종, 세부 구분, 공정 중 하나라도 직접 입력으로 추가했을 때만 true. 코드에서 읽는 곳은 없음 |

- 구형 호환: `problem.industry`, `subIndustry`, `process`, `aiFunction`(단일 값)이 있고 targets 배열이 없으면 targets 한 개로 변환하고 옛 키를 지움

### 2.3 (2) 공정, 설비, 수집 장치: model.site

기본값 `{steps:[], equipment:[], devices:[], images:[]}`

| 키 | 화면 이름 | 형식 |
|---|---|---|
| steps | 상세 공정 * | 객체 배열 |
| equipment | 설비 (해당 시 작성) | 객체 배열 |
| devices | 수집 장치 * | 객체 배열 |
| images | 대표 이미지 (상세 공정 아래, 선택) | 이미지 객체 배열 |

steps 원소 (`blankD2().step` 기준, 모든 키 문자열, 없으면 `""`로 채움):

| 키 | 화면 이름 | 비고 |
|---|---|---|
| id | ID | `P`+정수. 불러오기 때 자동 부여되지 않음. 직접 지정해야 함 |
| target | 대상 공정 * | T# 참조 (problem.targets[].id) |
| name | 상세 공정명 | 비우면 대상 공정의 공정명과 같은 것으로 표시 |
| prev | 전공정 (선택) | 자유 문자열 |
| next | 후공정 (선택) | 자유 문자열 |
| workMode | 작업 방식 | WORK_MODES 중 하나 또는 `""` |
| cycleTime | 1회 작업 시간 | 자유 문자열. 연속 생산이면 비움 |
| splitBy | 작업 구분 방법 | SPLIT_BY 중 하나 또는 `""` |
| splitKey | 번호 이름 | splitBy가 SPLIT_BY 첫 항목일 때만 입력됨. 그 외 `""` |
| desc | 상세 설명 (선택) | 줄바꿈 가능한 평문 |

equipment 원소 (설비):

| 키 | 화면 이름 | 비고 |
|---|---|---|
| id | ID | `E`+정수. 자동 부여 안 됨 |
| step | 상세 공정 * | P# 참조 |
| name | 설비명 * | |
| code | 설비 번호 및 모델 | |
| maker | 제조사 | |
| spec | 주요 사양 | |
| desc | 상세 설명 (선택) | |

devices 원소 (수집 장치):

| 키 | 화면 이름 | 비고 |
|---|---|---|
| id | ID | `S`+정수. 자동 부여 안 됨 |
| step | 상세 공정 * | P# 참조 |
| equip | 설치 설비 * | E# 참조. 설비에 직접 설치되지 않으면 `""` (화면 표시 "설비에 설치 안 됨", 선택값은 `-`) |
| name | 장치명 * | |
| kind | 종류 * | DEVICE_KINDS 중 하나 |
| kindText | 종류 입력 | kind가 `직접 입력`일 때만 값 (필수). 그 외 `""` |
| item | 측정 항목 | |
| loc | 설치 위치 (상세) | 줄바꿈 가능 |
| product | 제품명 | 구형 `spec`이 있으면 product로 옮기고 spec 삭제 |
| maker | 제조사 | |
| props | 종류별 특성 | 객체. 키는 아래 DEVICE_PROPS의 key. 값이 있는 키만 저장 |
| desc | 상세 설명 (선택) | |

DEVICE_PROPS (종류별 특성 key, 화면 이름):

| kind | props 키 : 화면 이름 |
|---|---|
| `센서` | range : 측정 범위, accuracy : 정확도 및 분해능, unit : 출력 단위, interval : 수집 주기 |
| `카메라` | resolution : 해상도, fps : 프레임 속도, fov : 시야 및 렌즈, mode : 촬영 방식 |
| `검사기` | method : 검사 방식, detect : 검출 성능, speed : 검사 속도, output : 결과 형식 |
| `계측기` | range : 측정 범위, accuracy : 정확도 및 분해능, unit : 출력 단위, interval : 측정 주기 |
| `PLC·제어기` | signals : 수집 신호 수, protocol : 통신 방식, interval : 수집 주기, controller : 기종 |
| `시스템(MES·ERP 등)` | system : 시스템명 및 버전, items : 기록 항목, interval : 기록 시점 및 주기, link : 연동 방식 |
| `직접 입력` | note : 특성 (자유 기술 한 칸) |

- 위 표의 화면 이름은 가운뎃점을 '및'으로 바꿔 적음. 화면에 보이는 원문 이름과 입력 예시는 부록 D. 저장 데이터에는 key만 들어감
- kind를 바꾸면 화면에서는 props가 초기화됨. 값이 해당 kind의 key에 없으면 화면, 내보내기에서 표시되지 않음
- 구형 호환: kind `기타`는 `직접 입력`으로 바꿈

### 2.4 (3) 원시 데이터: model.datasets[]

공통 필드 (`blankDs(id,type,name)` 기본값):

`{id, type, name, period:'', source:'', sourceText:'', count:'', sizeMB:'', format:'', devices:[], desc:'', kv:{}, rows:[], raw:{grid:blankGrid(), images:[], text:''}}`

| 키 | 화면 이름 | 형식 | 비고 |
|---|---|---|---|
| id | ID | `D`+정수 | 없으면 `nextId`로 부여 |
| type | 데이터 유형 * | DS_TYPES 키 | `timeseries`, `tabular`, `image`, `video`, `text`, `3d`, `other`. 이 외 값이면 해당 데이터가 불러오기 때 통째로 버려짐 |
| name | 데이터명 * | 문자열 | 예) 열처리로 온도 센서 데이터 |
| period | 수집 기간 * | 문자열 | 예) 2024.04 ~ 2025.03 |
| source | 데이터 출처 * | `현장`, `실험실`, `혼합`, `기타` | 4장 |
| sourceText | (기타 선택 시) 직접 입력 | 문자열 | source가 `기타`일 때 표시 `기타 (입력값)` |
| count | 건수 * | 숫자 문자열(정수) | 쉼표 불가. 정수 형식이 아니면 `""`로 지워짐 |
| sizeMB | 용량 * (MB) | 숫자 문자열(소수 가능) | 쉼표 불가. 형식이 아니면 `""`로 지워짐 |
| format | 저장 형식 | 문자열 | 예) csv, png, mp4. 별표 없음 |
| devices | 수집 장치 * | S# 문자열 배열 | 없는 S#는 제거됨. 화면에서 체크할 때는 site.devices 순서로 정렬됨 |
| desc | 설명 (선택) | 평문 | 구형 `scale`이 있으면 `규모: ...`로 desc 앞에 합치고 scale 삭제 |
| kv | 유형별 상세 정보 | 객체 | 아래 유형별 표 |
| rows | 변수 목록, 항목 목록 또는 라벨 종류 | 객체 배열 | 아래 |
| raw | 원시 데이터 예시 * | 객체 | grid, images, text 중 유형별로 쓰이는 것만 의미 있음 |

건수 단위 표시(COUNT_UNIT): timeseries 건, tabular 건, image 장, video 개, text 건, 3d 건, other 건 (화면 표시용, 저장 값에는 없음)

DS_TYPES 유형별 kv 필드 (kv 키 : 화면 이름, 필수는 *):

| type | 화면 이름 | kv 필드 | rows 용도 | raw 사용 | rawHint 요약 |
|---|---|---|---|---|---|
| timeseries | 시계열 | interval : 수집 주기 * | 변수 목록 (VAR_COLS) | grid | |
| tabular | 테이블형 | rowUnit : 한 줄(1건)의 기준 *, when : 기록 시점 | 항목 목록 (VAR_COLS) | grid | |
| image | 이미지 | target : 촬영 대상 *, camera : 촬영 방식 *, resolution : 해상도, label : 라벨 *, labelDesc : 라벨 설명 | 라벨 종류 (LABEL_COLS), label이 `있음`일 때만 | images | 라벨이 있으면 라벨 유형별 1장 이상 |
| video | 영상 | target : 촬영 대상 *, resolution : 해상도, fps : 초당 프레임, clip : 영상 1개의 단위, label : 라벨 *, labelDesc : 라벨 설명 | 라벨 종류, label이 `있음`일 때만 | images | 작업 단계별 대표 이미지 2~3장 |
| text | 텍스트 | docType : 문서 종류 *, form : 작성 방식, writer : 작성자, privacy : 개인정보 | 없음 | text | |
| 3d | 3D | target : 측정 대상 *, shape : 데이터 형태 *, unit : 측정 단위, size : 1건의 크기, label : 라벨 *, labelDesc : 라벨 설명 | 라벨 종류, label이 `있음`일 때만 | images 및 text | 뷰어 캡처 이미지, 앞부분 텍스트 |
| other | 기타 | unitDesc : 1건의 구성 *, tool : 데이터를 여는 방법 | 없음 | images 및 text | 이미지 또는 텍스트 1건 이상 |

kv 필드 중 선택 목록이 있는 것:

| 필드 | 허용 값 |
|---|---|
| kv.camera (image) | `일반 카메라 (컬러)`, `일반 카메라 (흑백)`, `열화상`, `X-ray`, `현미경`, `기타` |
| kv.label (image, video, 3d) | `있음`, `없음` |
| kv.form (text) | `자유롭게 작성`, `정해진 양식에 작성`, `혼합` |
| kv.privacy (text) | `포함 안 됨`, `포함 - 가림 처리함`, `포함 - 처리 안 함` |
| kv.shape (3d) | `점 데이터 (포인트클라우드)`, `단면 영상 (CT 등)`, `형상 모델 (메시)`, `기타` |

- labelDesc: label이 `있음`일 때만 입력란이 보임. `없음`이어도 값은 지워지지 않으나 읽기 화면과 내보내기에서는 제외됨
- label이 `없음`일 때 설명(desc)에 "정상 제품 사진만 수집" 같은 안내가 placeholder로 뜸 (저장 값 아님)
- 구형 호환: kv.label이 `정상 데이터만 있음`이면 `없음`으로 바꾸고 desc 앞에 `정상 데이터만 수집` 추가. 그 외 목록에 없는 label 값은 `있음`으로 시작하면 `있음`(남은 글자는 labelDesc가 비었을 때 labelDesc로), 아니면 `없음`
- image 유형에서 이미지를 화면으로 추가하면 kv.resolution이 비어 있을 때 `원본폭 × 원본높이`로 자동 채움 (프로그램 입력에서는 해당 없음)

rows 원소 (열 키 : 화면 이름, 필수는 *):

| 용도 | 키 : 화면 이름 |
|---|---|
| VAR_COLS (변수 목록, 항목 목록) | name : 변수명 *, desc : 설명, unit : 단위, device : 수집 장치 (S# 또는 `""`), vtype : 값 종류, use : 사용 |
| LABEL_COLS (라벨 종류) | cls : 라벨명 *, def : 설명, count : 건수 (숫자) |

- vtype 허용 값(VALTYPE): `숫자`, `문자`, `날짜·시각`, `구분값`. 불러오기 때 검사하지 않음
- use 허용 값(USE): `모델 입력`, `예측 대상`, `미사용`. 불러오기 때 별칭 변환 (아래), 변환 안 되면 `""`
- use 별칭(USE_ALIAS, 소문자 비교): `input`, `입력` 은 `모델 입력`. `target`, `output`, `출력`, `정답` 은 `예측 대상`
- rows의 device는 S# 참조. 없는 S#는 `""`로 지워짐
- rows 원소는 객체여야 함 (null이면 `normalize`에서 예외, 가드 없음)
- 화면에서 빈 행은 읽기, PDF, 내보내기에서 제외됨. 모든 값이 빈 행 기준

raw 구조:

| 키 | 형식 | 비고 |
|---|---|---|
| grid | `{cols:[문자열...], rows:[[문자열...]...]}` | cols와 rows가 둘 다 배열이 아니면 기본 표로 되돌림. 기본 표는 `cols:['컬럼 1','컬럼 2','컬럼 3','컬럼 4']`, rows는 빈 문자열 4칸짜리 2행 |
| images | 이미지 객체 배열 | 6장. 유효하지 않은 이미지는 제거됨 |
| text | 문자열 | 원문 일부 |

- 기본 표(전부 빈 칸)는 "비어 있음"으로 판정됨 (`gridEmpty`: 어떤 행에도 비어 있지 않은 칸이 없음). 값이 있는 행이 1개 이상이어야 "예시 있음"
- grid 행 길이는 cols 수와 맞추는 것이 안전함. 화면은 `r[i]`로 읽으며 모자라면 빈 칸

### 2.5 (4) 전처리 데이터: model.prep

기본값 `{steps:[], episodes:[], results:{}, example:{grid:blankGrid(), images:[]}}`

| 키 | 화면 이름 | 형식 | 비고 |
|---|---|---|---|
| steps | 처리 단계 | 배열 | 원소 `{id, targets, method, detail}` |
| steps[].id | (내부) 순서 번호는 배열 순서 | `R`+정수 | 없으면 부여. 화면의 "순서"는 배열 위치 |
| steps[].targets | 대상 데이터 * | D# 문자열 배열 | 없는 D#는 제거. 빈 배열이 되면 단계 전체가 삭제됨 |
| steps[].method | 처리 방법 * | 문자열 | 예) 이상치 제거 (IQR 기준) |
| steps[].detail | 상세 내용 (선택) | 평문 | |
| episodes | 학습 사용 구간 (에피소드) (해당 시) | 배열 | 원소 `{targets, range}`. targets 규칙은 steps와 같고 빈 배열이면 삭제 |
| episodes[].range | 사용 구간 * | 평문 | |
| results | 전처리 결과 | 객체 | 키 = D#, 값 `{count, sizeMB}` (둘 다 숫자 문자열). 없는 D# 키는 삭제. 숫자 형식이 아니면 해당 값만 `""` |
| example.grid | 전처리 결과 예시 표 (선택) | grid | 2.4 raw.grid와 같은 규칙 |
| example.images | 전처리 결과 예시 이미지 (선택) | 이미지 배열 | 6장 |

- 전처리 결과 입력란은 화면에서 "처리 단계 targets에 포함된 데이터"에만 열림. 포함되지 않은 데이터는 "전처리 없음 (원시 데이터 그대로 사용)"으로 표시되고 `results`에는 값을 넣지 않아도 됨 (넣어도 D#가 유효하면 보존됨)
- 구형 호환: 예전 파일은 입력과 출력(`io`), `ioInit`, 학습 비율(`split`)이 `prep` 안에 있었고, `m.ready`가 없으면 ready로 옮김

### 2.6 (5) AI 준비 데이터: model.ready

기본값 `{io:[], ioInit:false, joinBy:'', split:{train:'',val:'',test:''}}`

| 키 | 화면 이름 | 형식 | 비고 |
|---|---|---|---|
| io | 모델 입력 및 출력 * | 배열 | 원소 `{role, ds, dsName, item, shape}` |
| io[].role | 구분 * | `입력` 또는 `출력` | 그 외 값은 `입력`으로 바뀜 |
| io[].ds | 데이터 * | D# 또는 `""` | D#가 유효하지 않으면 해당 행 삭제. `""`이면 직접 입력 행 |
| io[].dsName | 데이터 이름 (직접 입력) | 문자열 | ds가 `""`일 때 사용. 화면 추가 때는 직접 입력이면 필수 |
| io[].item | 항목 * | 문자열 | 예) Temp_Z1, Temp_Z2 |
| io[].shape | 만든 방법 및 형태 (선택) | 문자열 | |
| ioInit | (없음) | 불리언 | 입력 및 출력 자동 채움을 했는지 표시. 7.4 참조 |
| joinBy | 데이터 간 맥락 연결 > 연결 기준 (해당 시) | 문자열 | |
| split.train | 학습 (%) * | 숫자 문자열 (소수 가능) | 형식이 아니면 `""` |
| split.val | 검증 (%) | 숫자 문자열 | |
| split.test | 테스트 (%) * | 숫자 문자열 | |

- 합계가 100이 아니면 화면 합계 표시가 붉게 바뀔 뿐 저장은 막히지 않음 (`t!==100`일 때 'bad' 클래스)
- 구형 호환: `split.basis` 키는 삭제됨

`blankAi()` 기본값: `{algo:'', learnType:'', learnTypeText:'', task:'', taskText:'', metrics:[], params:[], framework:'', gpu:'', gpuCount:'', hw:'', devEnv:'', fileFormat:''}`

| 키 | 화면 이름 | 형식 | 비고 |
|---|---|---|---|

| gpu | GPU 제품명 | 문자열 | |
| gpuCount | GPU 개수 | 정수 문자열 | 형식이 아니면 `""` |
| hw | 학습 장비 (CPU 및 메모리 등) | 문자열 | |
| devEnv | 개발 도구 및 OS | 문자열 | |
| fileFormat | 모델 파일 형식 | 문자열 | 예) .pt, .pkl, .onnx |

metrics 원소 (METRIC_COLS): name : 성능 지표 *, target : 목표값, result : 결과값, note : 비고

- metrics, params는 배열이어야 하고 원소는 객체만 남김 (객체가 아닌 원소는 제거)
- 화면 (6) 단계를 열면 빈 배열일 때 `{}` 행이 1개 추가됨. 모든 값이 빈 행은 읽기, PDF, 내보내기에서 제외됨
- 모델 개요 화면의 "모델 입력 및 출력" 표는 (5)의 ready.io를 보여 주는 읽기 전용 참조이며 별도 저장 필드 없음

|---|---|---|---|
| note | 기타 사항 (선택) | 서식 있는 글 | 없으면 `""` |

- etc가 객체가 아니면 `{note:''}`로 대체

### 2.9 서식 있는 글 필드 (overview, effect, processNote, etc.note)

- 저장 값은 HTML 문자열 또는 평문. HTML 태그(`b`, `strong`, `ul`, `ol`, `li`, `br`, `div`, `p`)가 하나라도 보이면 HTML로 취급(`looksHtml` 정규식 `/<\/?(b|strong|ul|ol|li|br|div|p)\b/i`)
- 허용 태그: `b`(`strong` 포함 변환), `ul`, `ol`, `li`, `br`, `div`(`p`는 `div`로 변환). 속성은 모두 제거. `script`, `style`, `iframe`, `object`, `embed`, `template`는 내용까지 삭제. 그 외 태그는 태그만 벗기고 글자 유지
- 화면에서 편집하면 저장 값은 `sanitizeRich` 결과 HTML. 샘플은 `<div>문단</div><div>문단</div>`, `<ul><li>항목</li></ul>`, `<b>굵게</b>` 형태
- 글자가 없고 `li`도 없으면 `""`로 저장
- 평문(HTML 태그 없음)을 넣으면 그대로 표시됨. 줄바꿈이 편집 화면에서 보존되는지는 코드(CSS 포함)에서 확인 못 함. 문단 구분은 `<div>` 사용 권장
- 평문 입력란(textarea)은 `desc`, `detail`, `range`, `loc`, `labelDesc`, `raw.text` 등이며 `\n` 줄바꿈 사용

## 3. 필수 항목(*)과 검증 규칙

### 3.1 검증이 실제로 일어나는 곳 (코드에서 확인됨)

| 위치 | 규칙 | 위반 때 동작 |
|---|---|---|
| 저장, 내보내기 | 검사 없음 | - |
| 대상 업종 및 공정 "추가" | 최대 5개(`MAX_TARGETS`). 6번째부터 선택칸 비활성화 및 토스트 `최대 5개까지 추가할 수 있습니다` | 추가 안 됨 |
| 위 같은 곳 | 업종, 세부 구분, 공정, AI 기능이 모두 채워져야 함 (세부 구분은 아래 예외) | 토스트, 추가 안 됨 |
| 위 같은 곳 | 같은 `업종 > 세부 구분 > 공정`과 같은 AI 기능 중복 불가 | 토스트 `이미 추가된 항목입니다` |
| 상세 공정 "추가" | 대상 공정(T#) 필수. 같은 target과 같은 name(공백 제거) 중복 불가 | 토스트, 추가 안 됨 |
| 설비 "추가" | 상세 공정, 설비명 필수 | 토스트 |
| 수집 장치 "추가" | 상세 공정, 설치 설비(설비 없음 포함), 장치명, 종류 필수. 종류가 `직접 입력`이면 종류 입력도 필수 | 토스트 |
| 원시 데이터 "추가" | 데이터 유형, 데이터명 필수 | 토스트 |
| 전처리 단계 "추가" | 대상 데이터 1개 이상, 처리 방법 필수 | 토스트 |
| 사용 구간 "추가" | 대상 데이터 1개 이상, 사용 구간 필수 | 토스트 |
| 모델 입력 및 출력 "추가" | 구분, 데이터 필수. 직접 입력이면 데이터 이름 필수. 항목 필수 | 토스트 |
| 숫자 칸 (건수, 용량, 전처리 후 건수 및 용량, 학습 검증 테스트 비율, GPU 개수, 라벨 건수) | 건수, GPU 개수, 전처리 후 건수는 정수만, 용량 및 비율은 소수 가능, 라벨 건수는 소수 가능. 쉼표는 입력 시 제거 | 입력 되돌림, 토스트 `숫자만 입력할 수 있습니다` |
| 표 붙여넣기 | 선택 칸은 목록 값과 대소문자 무시로 일치하거나(사용 칸은 별칭 포함) 아니면 `""`. 수집 장치 칸은 S#, 장치명, `S# 장치명`만 인정 | 값 비움 |
| 불러오기(`normalize`) | 5장 | 조용히 수정, 삭제 |

- 세부 구분 예외: 업종이 세부 구분 없는 업종(키가 `""`)이거나 업종을 직접 입력하면 세부 구분은 비어도 됨. 업종은 목록이고 세부 구분이 있는 업종이면 세부 구분 필수
- 숫자 판정(`isNum`): 정수는 `/^\d+$/`, 소수는 `/^(\d+\.?\d*|\.\d+)$/`, 빈 값은 통과. 불러올 때는 쉼표 제거를 하지 않으므로 `"12,568"`은 `""`로 지워짐

### 3.2 화면 별표 기준 필수 항목 (저장은 막히지 않음)

플랫폼의 제출 검증이 있다면 참고할 후보 목록이며, 제출 검증 규칙 자체는 코드에서 확인 못 함.

| 단계 | 필수(*) 항목 |
|---|---|
| 기본 정보 | writerOrg(기관명), writerRegion(작성 기관 소재 지역) |
| (1) 문제 정의 | name, problem.company, problem.companyRegion, problem.overview, problem.targets 1개 이상(제목 별표), problem.effect. 대표 이미지는 선택 |
| (2) 공정, 설비, 수집 장치 | site.steps 1개 이상(제목 별표), site.devices 1개 이상(제목 별표). 설비는 "해당 시 작성". 추가 때 필수 입력은 3.1 표 |
| (3) 원시 데이터 | datasets 1개 이상(제목 별표). 데이터마다: name, type, source(`기타`면 sourceText), period, count, sizeMB, devices(제목 별표), raw 예시(제목 별표), 유형별 kv 별표 항목(2.4 표), rows 표의 별표 열(name 또는 cls) |
| (4) 전처리 | 모두 선택 (전처리 없으면 steps 비움). 단계를 추가하는 경우 targets, method 필수 |
| (5) AI 준비 데이터 | ready.io 1개 이상(제목 별표), split.train, split.test (검증은 별표 없음) |
| (6) AI 모델 | ai.algo, ai.learnType, ai.task, ai.metrics 1개 이상(제목 별표, name 열 별표) |
| (7) 기타 | 선택 |

- 이미지 유형 라벨: label(있음 또는 없음)이 별표. `있음`이면 labelDesc 입력란이 열림(별표 없음)
- 원시 데이터 예시 필수 판단 기준: grid 유형은 값이 있는 행 1개 이상, images 유형은 이미지 1장 이상 안내(rawHint). text 유형은 raw.text 비어 있지 않음. 어느 것도 코드로 강제되지 않음

## 5. ID 연결 규칙과 정리 로직

### 5.1 ID 형식

| 대상 | 접두 | 예 | 자동 부여 |
|---|---|---|---|
| 대상 업종 및 공정 | T | T1 | 불러오기 때 비어 있으면 부여 (`nextId`) |
| 상세 공정 | P | P1 | 불러오기 때 부여 안 됨 |
| 설비 | E | E1 | 안 됨 |
| 수집 장치 | S | S1 | 안 됨 |
| 원시 데이터 | D | D1 | 부여됨 |
| 전처리 단계 | R | R1 | 부여됨 |

- `nextId(list,prefix)`는 접두 뒤 숫자의 최대값 + 1. 삭제된 번호는 재사용하지 않음 (샘플의 전처리 단계가 R2, R3 로 시작함)
- ID 유일성 검사는 코드에 없음. 중복 ID를 넣으면 참조가 첫 번째 항목으로 해석되어 어긋남
- 모델 id(숫자)는 모델 추가, 삭제 때 `1..n` 으로 다시 매김

### 5.2 참조 관계

| 참조하는 쪽 | 참조받는 쪽 | 끊어졌을 때 |
|---|---|---|
| site.steps[].target | problem.targets[].id (T#) | 불러오기와 렌더링에서 지우지 않음. 화면 "(대상 공정 미선택)" 또는 대상 공정 칸 빈 값 |
| site.equipment[].step | site.steps[].id (P#) | 지우지 않음. 화면 `-` |
| site.devices[].step | site.steps[].id | 지우지 않음. 화면 `-` |
| site.devices[].equip | site.equipment[].id (E#) 또는 `""` | 지우지 않음. `""`은 "설비에 설치 안 됨", 없는 E#는 `-` |
| datasets[].devices[] | site.devices[].id (S#) | `cleanRefs`가 배열에서 제거 |
| datasets[].rows[].device | site.devices[].id | `cleanRefs`가 `""`로 변경 |
| prep.steps[].targets[] | datasets[].id (D#) | `cleanPrep`이 제거. 빈 배열이 되면 단계 삭제 |
| prep.episodes[].targets[] | datasets[].id | 위와 같음 |
| prep.results 키 | datasets[].id | 해당 키 삭제 |
| ready.io[].ds | datasets[].id | `ds`가 비어 있지 않고 D#가 없으면 행 삭제 (ds가 `""`이면 보존) |

### 5.3 정리 함수

| 함수 | 시점 | 하는 일 |
|---|---|---|
| `normalize(st)` | 시작 때 form-data 읽은 직후, 취합 불러오기, 임시 저장 복구 | 최상위 기본값 채움, 모델 기본 구조 채움, 문자열 키 null 은 `""`로, targets, 데이터 ID 부여, 데이터 유형, 숫자, 이미지 검증, 구형 키 변환, 마지막에 `cleanRefs`, `normPrep`, `cleanPrep`, `normAi` 호출, 이미지 목록 정리 |
| `cleanRefs(m)` | `normalize`, 모든 `render()`, 수집 장치 삭제 | 5.2의 데이터에서 수집 장치 참조 제거 |
| `normPrep(m)` | `normalize` | prep.steps를 `{id,targets,method,detail}` 로 재구성(다른 키는 버림), id 없으면 R# 부여. episodes 를 `{targets,range}`로 재구성. results의 count, sizeMB 숫자 판정. `m.ready`를 만들고 `io` 원소를 `{role,ds,dsName,item,shape}`로 재구성. split 숫자 판정. example 정리 |
| `cleanPrep(m)` | `normalize`, 모든 `render()` | 5.2의 D# 참조 정리 |
| `normAi(m)` | `normalize` | ai 기본 키 채움, `gpuCount` 정수 판정, task 목록 밖 값을 기타로 이동, metrics 및 params 객체만 남김, etc 보정 |
| `seedIO(m)` | (5) 단계 화면을 열 때만 (`readySections`) | `ready.ioInit`이 false 이고 `ready.io`가 비어 있으면, 각 데이터의 rows에서 `use`가 `모델 입력`인 변수명들을 쉼표로 이어 `{role:'입력', ds:D#, item:'a, b', shape:''}` 로, `예측 대상`이면 `{role:'출력', ...}` 로 추가. 한 번 실행하면 `ioInit=true` |

- `render()`는 매번 `cleanRefs`와 `cleanPrep`을 먼저 실행하므로, 데이터와 수집 장치가 삭제되면 저장 전에 참조가 사라짐
- `normalize`는 site 내부 참조(P#, E#, T#)를 정리하지 않음. UI에서는 삭제 때 연쇄 삭제(`removeTarget`, `removeStep`)로 맞춰 둠

### 5.4 프로그램으로 채울 때 지킬 순서와 금지 사항

순서

1. problem.targets (T1...) 를 먼저 만들고 모든 값 확정
2. site.steps (P#, target=T#) 를 만들고, 이어서 site.equipment (E#, step=P#), site.devices (S#, step=P#, equip=E# 또는 `""`)
3. datasets (D#) 를 만들고 `devices`(S#), `rows[].device`(S#)를 채움. 수집 장치가 먼저 있어야 함
4. prep.steps, prep.episodes, prep.results (D# 참조)
5. ready.io (D# 참조), joinBy, split
6. ai, etc, 이미지는 마지막에 data URL로 삽입
7. 모델 id 를 1부터 순번, writerOrg, writerRegion 설정(모델 org, orgRegion 은 같은 값)

금지 및 주의

- 존재하지 않는 D#, S# 를 참조하면 조용히 삭제됨. P#, E#, T# 는 삭제되지 않고 어긋난 채 표시됨
- ID는 접두 + 정수(`T1`, `P1`, `E1`, `S1`, `D1`)로 유일하게 부여. P, E, S 는 반드시 직접 부여(자동 부여 안 됨)
- 숫자 필드는 문자열이며 쉼표 금지, 단위 문자 금지(`"1,200 MB"` 는 비워짐). 건수와 GPU 개수는 정수
- 배열 자리에 `null` 금지 (`steps`, `equipment`, `devices`, `images` 등 값이 null 이면 `Object.assign`이 기본값을 덮어써 예외 가능). 모델 및 rows 원소가 null 이면 예외
- datasets[].type 은 DS_TYPES 키만 사용. 다른 값은 데이터가 삭제되고 그 데이터를 참조하는 전처리 및 입출력 행도 함께 정리됨
- label 은 `있음`/`없음` 만. labelDesc 와 라벨 rows 는 `있음`일 때만 의미가 있음
- 이미지는 6장 조건을 지킬 것. 조건에 맞지 않으면 조용히 제거됨
- rows[].use 는 목록 값 3개만, 별칭은 `input` 등 6개만 변환됨
- targets 는 최대 5개로 맞출 것 (코드가 자르지는 않으나 화면 한도)
- 같은 업종, 세부 구분, 공정, AI 기능 조합과 같은 (target, name) 상세 공정 중복 금지 (화면 규칙)

## 6. 저장 방식, 파일명, 불러오기

### 6.1 serialize

```js
function serialize(src){
  syncOrg(); S.role=APP_MODE;
  if(!src){ S.formVersion=FORM_VERSION; S.savedAt=new Date().toISOString(); }
  const json=JSON.stringify(src||S).replace(/</g,'\\u003c');
  const re=new RegExp('(<script type="application/json" id="'+DATA_ID+'">)[\\s\\S]*?(</scr'+'ipt>)');
  return TEMPLATE.replace(re,(x,a,b)=>a+json+b);
}
```

- `TEMPLATE` 는 스크립트 시작 때 `'<!DOCTYPE html>\n' + document.documentElement.outerHTML` 로 잡은 원본(렌더 전). form-data 블록 내용만 교체해서 전체 HTML 파일을 만듦
- 저장 값: `JSON.stringify(S)` (공백 없는 한 줄). 한글 등은 이스케이프하지 않고 그대로 씀
- 이스케이프: `<` 만 `<` 로 바꿈 (`</script>`, `<!--` 방지). `>`, `&` 는 그대로. JSON.parse 가 `<` 를 `<` 로 복원
- 교체는 함수 치환(`(x,a,b)=>a+json+b`)이라 JSON 안의 `$` 가 특수 처리되지 않음
- 블록 인식 정규식은 `<script type="application/json" id="form-data">` 문자열을 정확히 요구함 (속성 순서, 큰따옴표, 공백 한 칸)
- `serialize(src)` 의 `src` 인자 경로는 코드 안에서 호출하는 곳이 없음 (모두 `serialize()`)
- 저장 동작(`save`): Blob(text/html) 생성. File System Access API(`showSaveFilePicker`)가 있으면 파일 선택, 없으면 다운로드. 같은 파일 핸들을 재사용(`save(false)`), `다른 이름으로 저장`은 핸들 초기화. Ctrl+S, [저장] 단추(`#bSave`), 메뉴 모두 같은 `save`
- `페이지 저장` 단추(모델 작성 화면 아래)는 파일 저장이 아님. `localStorage` 임시 저장만 함
- 임시 저장 키: `'aispec-backup:' + location.pathname`. 입력 후 10초, 단계 이동, 목록 이동, 화면 숨김 때 기록. 파일 저장하면 삭제. 시작 때 `modifiedAt` 이 더 새로운 임시 저장이 있으면 복구 배너 표시. 프로그램으로 만든 파일은 `modifiedAt:null`이므로 같은 경로에 임시 저장이 있으면 배너가 뜰 수 있음

### 6.2 파일명 (fileName)

- 작성용: `AI학습데이터명세서_작성_{writerOrg}_{project.number}.html`
- 취합용: `AI학습데이터명세서_취합_{project.number}_{project.leadOrg}.html`
- 각 부분은 `clean()` 적용: 앞뒤 공백 제거, `\ / : * ? " < > |` 및 공백 연속을 `_` 한 개로, 40자로 자름. 빈 부분은 건너뜀(`filter(Boolean)`)
- 작성용 샘플의 파일명 `AI학습데이터명세서_작성_A사.html` (project.number 가 비어 있어 생략됨)
- 이 파일명은 저장 시 제안 이름일 뿐이며 형식 강제나 검사는 코드에 없음. 플랫폼의 파일명 규칙은 코드에서 확인 못 함

### 6.3 불러오기 (extractData)와 받아들이는 모양

- `extractData(text)`: 앞뒤 공백 제거 후 `{`로 시작하면 JSON 전체로 파싱(JSON 파일). 아니면 HTML에서 `<script type="application/json" id="form-data">...</script>` 를 정규식으로 찾아 첫 번째 블록을 JSON 파싱. 블록이 없으면 `명세서 파일이 아닙니다` 예외. 블록이 비어 있으면 `{}`
- 취합용 가져오기(`pickImport`)는 `.html`, `.htm`, `.json` 파일을 여러 개 받음. 결과에 `models` 배열이 없으면 "작성된 AI 모델이 없습니다"
- 작성용 화면 시작 때는 같은 형식의 form-data 블록을 `JSON.parse` 하며 `{}` 또는 빈 문자열이면 빈 상태

### 6.4 취합용(APP_MODE 'lead')과의 차이

| 항목 | 작성용 (writer) | 취합용 (lead) |
|---|---|---|
| APP_MODE | `'writer'` | `'lead'` (이 파일에서는 상수 주석으로만 확인. 취합용 HTML 은 읽지 않음) |
| 화면 | 작성 (기본 정보, 모델 작성 7단계) | 과제 정보 작성 및 취합, 모델 읽기 전용 보기 |
| project 입력 | 없음 | 과제명 *, 과제번호 *, 주관기관 *, 작성자 *, 연락처, 작성일 |
| 불러오기 메뉴 | 숨김 | 표시. 작성 파일(HTML, JSON) 여러 개 불러옴 |
| org 동기화(`syncOrg`) | 저장 때 모델 org 를 writerOrg 로 덮어씀 | 하지 않음 |
| 불러올 때 | - | `normalize(d)` 후 org 가 비어 있으면 파일의 writerOrg 로 채움. `과제번호` 가 다르면 확인창. 빈 모델(`isBlankModel`: 이름, 데이터, 문제 개요, 대상 공정이 모두 비어 있음)은 건너뜀. 같은 `org|name` 모델은 덮어씀, 아니면 추가. 끝에 모델 id 1..n 재부여 |
| 파일명 | `AI학습데이터명세서_작성_기관_과제번호.html` | `AI학습데이터명세서_취합_과제번호_주관기관.html` |

- 두 모드는 같은 저장 JSON 구조를 씀. 최상위의 `role` 값으로 구분(`writer` 또는 `lead`)

## 7. 이미지 필드 형식

### 7.1 이미지 객체

| 키 | 형식 | 설명 |
|---|---|---|
| src | data URL 문자열 | 필수. 아래 조건 |
| name | 문자열 | 원본 파일명 (화면 표시에는 안 쓰임) |
| origW | 숫자 | 원본 가로(px). 화면에 `원본 W × H`로 표시 |
| origH | 숫자 | 원본 세로(px) |
| caption | 문자열 | 설명. 화면, PDF, 내보내기에 표시 |

- 값이 없으면 `원본 undefined × undefined` 처럼 표시될 수 있음. origW, origH 를 넣을 것
- 이미지가 들어가는 위치: `problem.images`, `site.images`, `datasets[].raw.images`, `prep.example.images`

### 7.2 safeImg 조건

```js
const safeImg=s=>/^data:image\/(jpeg|png|gif|webp);base64,[A-Za-z0-9+/=]+$/.test(String(s||''));
```

- 허용: `data:image/jpeg;base64,...`, `png`, `gif`, `webp`. `jpg`, `svg+xml`, `;charset=`, 줄바꿈, 공백 포함 base64 는 불허
- `normalize` 에서 `x.raw.images`, `problem.images`, `site.images`, `prep.example.images` 를 이 조건으로 거름. 조건에 안 맞는 이미지는 조용히 삭제됨. 렌더링 때도 같은 조건을 다시 검사해 안 맞으면 `img` 를 그리지 않음
- 이미지 항목이 객체가 아니거나 null 이어도 `e&&safeImg(e.src)` 로 제거됨

### 7.3 크기 제한

- 화면에서 추가할 때 긴 변을 1280px 로 줄이고(`MAX_SIDE=1280`), 흰 배경 위에 JPEG 품질 0.85 로 변환함(`JPEG_Q=0.85`). 결과 형식이 항상 `data:image/jpeg;base64,...`
- 파일 크기, 이미지 개수, 해상도 상한은 불러오기 및 저장 코드에 없음 (코드에서 확인 못 함). 플랫폼 쪽 한도도 확인 못 함
- 프로그램으로 넣을 때는 같은 방식(긴 변 1280px, JPEG)으로 줄이는 것을 권장하는 근거는 샘플이며, 샘플 이미지 객체 하나는 약 28~32 KB(data URL 길이 기준 약 2.8~3.2만 자)임
- 임시 저장(localStorage)은 용량 초과 시 예외를 삼키므로(`try/catch`) 이미지가 많으면 임시 저장이 안 될 수 있음. 파일 저장에는 영향 없음

## 8. 빈 양식의 form-data 블록만 바꿔 채울 때의 최소 조건

### 8.1 파일 조건

1. 빈 양식 HTML 을 UTF-8 로 읽어, `<script type="application/json" id="form-data">{}</script>` 의 `{}` 부분만 교체. 다른 부분(스크립트, 스타일, 헤더)은 그대로 둠. 파일 안에 이 블록은 1개이며 `</script>` 는 2개(블록, 스크립트)
2. 교체할 JSON 은 JSON.parse 가 통과해야 함. 문자열 안의 `<` 는 `<` 로 바꿀 것 (`</script>` 로 블록이 끊기지 않도록)
3. 최상위에 `role` 또는 `project`가 있어야 함 (`d.role!=null || d.project`). 없으면 데이터가 무시되고 빈 양식으로 열림
4. 인코딩은 UTF-8 (문서에 `<meta charset="utf-8">` 있음)
5. 블록 여는 태그 문자열이 정확해야 함: `<script type="application/json" id="form-data">`

### 8.2 정상 열림 조건

- 다음 조건에서 화면이 정상 열림: JSON 유효, 최상위에 role 또는 project 존재, `models` 가 배열(없으면 `[]` 로 대체), 각 모델이 객체, `site.*` 및 `prep`, `ready`, `ai` 의 배열 자리에 null 이 없음, `datasets[].rows` 의 원소가 객체
- 일부 키가 없어도 `normalize` 가 기본값을 채워 열림. `{"role":"writer","project":{},"models":[{"name":"x"}]}` 정도로도 열림 (코드 경로상 확인, 실행 시험은 하지 않음)
- 시작할 때 `normalize` 가 실행되므로 5장의 정리가 먼저 적용된 상태로 화면에 보임

### 8.3 [저장]과 제출 검증

- [저장](Ctrl+S 포함)은 아무 값 검사 없이 통과함. 최소 조건은 브라우저에서 HTML 파일이 열리고 저장 위치를 고를 수 있거나 다운로드가 허용되는 것뿐
- 제출 검증은 코드에 없음. 플랫폼이 form-data 의 어떤 필드를 필수로 보는지는 확인 못 함. 제출 파일에서 빠지지 않아야 한다고 코드에서 읽히는 항목은 3.2 표(별표)이며, 이를 프로그램 검사 규칙으로 쓸 때의 권장 점검 목록은 아래

권장 점검 목록 (3.1 추가 단추 조건과 3.2 별표에서 도출)

1. writerOrg, writerRegion 비어 있지 않음. writerRegion 은 REGIONS 값
2. 각 모델: name, problem.company, problem.companyRegion, problem.overview(글자 있음), problem.effect(글자 있음) 비어 있지 않음
3. problem.targets 1~5개. 각 원소 industry, process, aiFunction 비어 있지 않음. industry 가 목록이고 세부 구분이 있는 업종이면 subIndustry 도 목록 값. 중복 조합 없음
4. site.steps 1개 이상. target 이 problem.targets 의 id 에 존재. (target, name) 중복 없음
5. site.equipment 의 step 이 steps 에 존재, name 비어 있지 않음
6. site.devices 1개 이상. step 존재, equip 이 `""` 또는 equipment 에 존재, name 및 kind 비어 있지 않음. kind 가 DEVICE_KINDS 중 하나. kind 가 `직접 입력`이면 kindText 비어 있지 않음
7. datasets 1개 이상. type 이 DS_KEYS. name, period, source, count(정수 문자열), sizeMB(숫자 문자열) 비어 있지 않음. source 가 `기타`면 sourceText. devices 1개 이상이며 모두 존재하는 S#
8. 유형별 kv 별표 항목 비어 있지 않음. label 사용 유형(image, video, 3d)은 label 이 `있음`이면 labelDesc 도 채우고 rows 에 라벨 종류(cls 필수) 작성 권장
9. rows 의 name(또는 cls) 비어 있지 않음, use, vtype 이 목록 값, device 가 존재하는 S#
10. raw 예시: grid 사용 유형은 값 있는 행 1개 이상, images 사용 유형은 유효 이미지 1장 이상, text 유형은 raw.text 비어 있지 않음
11. prep.steps 의 targets 가 존재하는 D#, method 비어 있지 않음
12. ready.io 1개 이상. ds 존재하는 D# 이거나 `""`(이때 dsName 필수). role 이 `입력` 또는 `출력`. item 비어 있지 않음. split.train, split.test 비어 있지 않고 train+val+test 합계 100
13. ai.algo, ai.learnType, ai.task 비어 있지 않음. learnType 이 `기타`면 learnTypeText, task 가 `기타`면 taskText. ai.metrics 에 name 이 있는 행 1개 이상
14. 모든 이미지 src 가 safeImg 조건에 맞음
15. 모든 ID 가 접두 + 정수이며 해당 목록에서 유일함
